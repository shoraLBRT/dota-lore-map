# E14 · Партия героев — инструкция главному агенту

Для того, кто ведёт партию (#50–#58). Модель — **Sonnet**. Исследователи — субагенты **Haiku** (не справился — этот герой повторяется на Sonnet). Инструкция исследователя — [README.md](README.md); её читать нужно, остальные документы проекта целиком — нет: формат проверяют скрипты.

## Шаги

1. **Кэш** — по очереди, не параллельно (Liquipedia: только API, пауза ≥ 2 с — это делает скрипт):
   ```bash
   python research/e14/fetch.py <key> <key> ...
   ```
   «нет страницы» в выводе — добавить название страницы в `TITLES` в `fetch.py` и повторить.
2. **Исследователи** — по одному субагенту на героя, параллельно. В задании субагенту: ключ героя, путь к `research/e14/README.md`, путь к кэшу `research/e14/cache/<key>/`, «в сеть не ходить, править только `research/e14/heroes/<key>.json`, в конце запустить `python research/e14/check.py <key>`». Входящие связи от прошлых партий (`grep -l '"hero": "<key>"' research/e14/heroes/*.json`) — перечислить в задании.
3. **Сверка** — по каждому герою открыть `bio.en.txt`, `bio.ru.txt` и файл героя и пройти чек-лист ниже. Вики-текст читать только там, куда ссылается запись (`via`).
4. **Слияние и проверка:**
   ```bash
   python research/e14/check.py --merge <key> <key> ...
   python research/e1/build.py && npm run check
   ```
5. **PR** `content/<номер>-batch-NN`: таблица «было → стало» по каждому герою, что снято и почему, кандидаты в места, кто делал героя (Haiku / Sonnet). В `docs/PROJECT_STATE.md` — только отметить партию в списке и обновить строку счётчиков E14.

## Чек-лист сверки героя

Запись остаётся, только если её подтверждает источник нужной силы. Сильные источники: биография (`bio`), текст лор-страницы (`liquipedia` + `via: lore`), официальный комикс (`comic:<id>`). Слабые: инфобокс (`via: infobox`), упоминание на странице места (`via: place`).

**Снять (перенести в `unconfirmed`):**
- связь героя с героем или местом, которая держится только на **реплике озвучки**, шутке, фразе при убийстве;
- «знакомые» (раздел Acquaintances, «знает по имени») — тип связи из этого не выводится;
- раздел лор-страницы, целиком пересказывающий одну реплику или слух;
- всё из **Dota Underlords, Artifact, описаний предметов и наборов** — если это единственное основание (исключение: место названо в описании набора самого героя — можно оставить с `doubt`);
- **Dragon's Blood** — не источник мест и фактов (решение В5);
- догадки о регионе: «лес на западе → Западные леса», «родина неизвестна → ближайший регион»;
- кандидат в место без названия в источнике или не место вовсе (план бытия без имени, «мультивселенная», событие).

**Понизить:**
- место только в инфобоксе, в тексте биографии его нет → `mention` или оставить событие с `doubt`;
- «родина» по биографии оказалась походом или кампанией → `battle` / `visit`;
- дом, который источники не называют домом → `visit` региона целиком.

**Проверить всегда:**
- каждое место и событие из биографии RU и EN есть в файле (пропуск — главная ошибка Haiku);
- тип связи героев взят из текста, а не придуман («рад видеть» — не `enemy`);
- **взаимность**: связь с героем уже пройденной партии записать и в его файл (`research/e14/heroes/<other>.json`, затем `--merge` обоих); с героем будущей партии — только с одной стороны;
- герой без мест в лоре — `region: "uncharted"` с `note`, а не натянутая привязка;
- `summary` — своими словами, 3–5 предложений, без оценок и без пересказа механик игры;
- место, которого нет на схеме, — только в `candidates` (на карту его добавит #59).

**Не делать:** не править `regions.json`, `map/layout.json`, `content/`; не добавлять места; не читать ARCHITECTURE целиком — нужен только раздел A3 «Формат research/e1/hero-places.json», и только если `check.py` ругается непонятно.

## Когда остановиться и спросить владельца
- Источники противоречат друг другу в главном (родина, сторона) и биография не решает.
- Нужно новое место или регион, без которого герой остаётся в «Неизведанных землях», хотя место в биографии названо, — записать кандидатом и отметить в PR, партию не задерживать.
