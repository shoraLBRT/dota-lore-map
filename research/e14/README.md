# E14 · Сверка лора героя — инструкция исследователю

Ты исследуешь **одного героя** и записываешь результат в `research/e14/heroes/<key>.json`. Файл проверяет скрипт, потом главный агент сверяет его с биографией и сливает в данные карты. Эпик — #44, модель данных — #45 и [ARCHITECTURE A3](../../docs/ARCHITECTURE.md#a3-данные).

## 1. Что читать

Источники уже скачаны главным агентом в кэш `research/e14/cache/<key>/` (`python research/e14/fetch.py <key>`). Сам в сеть **не ходи**.

| Файл | Что это | В `read` |
|---|---|---|
| `bio.ru.txt`, `bio.en.txt` | официальная биография dota2.com, RU и EN | `bio.ru`, `bio.en` |
| `liquipedia-lore.wiki` | вики-текст страницы `<Герой>/Lore`: инфобокс (`places`, `origins`, `characters`) и заметки | `liquipedia-lore` |
| `liquipedia-hero.wiki` | вики-текст главной страницы героя | `liquipedia-hero` |
| `meta.json` | ссылки на страницы (`sources.*.url`) и чего нет (`missing`) | — |

Справочники (только читать):

- `research/e1/heroes.json` — ключи героев (`key`);
- `research/e1/regions.json` — регионы (`id`) и места на схеме (`locations[].name`);
- `research/e1/hero-places.json` — что о герое записано сейчас (было → стало сравнит главный агент);
- `content/media.json` — официальные комиксы (`id`), если герой в них есть.

**Обязательно прочитай обе биографии целиком.** Места часто спрятаны в середине текста: у Witch Doctor в биографии сказано «island highlands of Arktura», а в данных E1 он стоял в «Неизведанных землях».

## 2. Что записать

Скопируй [`template.json`](template.json) в `heroes/<key>.json` и заполни. Пустые необязательные списки (`path`, `relations`) лучше удалить, чем оставить с заглушками.

| Поле | Что | Обязательно |
|---|---|---|
| `hero` | key героя = имя файла | да |
| `read` | что ты действительно прочитал: `bio.ru`, `bio.en`, `liquipedia-lore`, `liquipedia-hero`, `comic:<id>` | да, минимум обе биографии |
| `links` | места героя, **по хронологии**: сначала родина, потом остальное | да, ≥ 1 |
| `path` | путь героя — остановки по порядку, только если герой действительно перемещался | нет |
| `relations` | связи с другими героями | нет |
| `profile.summary` | 2–3 предложения о герое своими словами, `ru` и `en`, ≤ 500 знаков каждое | да |
| `profile.art` | только официальные ссылки Valve (CDN `*.steamstatic.com`, `www.dota2.com`) | нет |
| `candidates` | места из лора, которых **нет** на схеме | нет |
| `unconfirmed` | что прочитал, но не смог подтвердить или привязать | да (может быть `[]`) |

### Связь герой–место (`links`)

- Место — `"place": "<имя из regions.json>"` (буква в букву) **или** `"region": "<id>"`, если известен только регион.
- Одно место — одна связь. Если в одном месте было несколько событий, выбери главное по порядку `origin` → `home` → `exile` → `battle` → `death` → `service` → `journey` → `visit` → `mention`, остальное — в `note`.
- Нет ни одного места в лоре — `{"region": "uncharted", "event": "origin", "source": "ours", "note": "почему"}`.

| `event` | Когда |
|---|---|
| `origin` | родина: родился, вырос, отсюда его народ или род; для пришельцев — родной план |
| `home` | живёт или базируется сейчас |
| `journey` | путь или переезд: пришёл сюда откуда-то |
| `battle` | сражение или нападение: бился, напал, разорил, осаждал |
| `service` | служба: служил, правил, охранял, состоял в ордене, учился |
| `exile` | изгнание или заточение: изгнан отсюда или заточён здесь |
| `death` | гибель или перерождение: погиб, убит, превращён, воскрес |
| `visit` | бывал, без важного события |
| `mention` | место только упомянуто рядом с героем (предмет, реплика, слух) — сам он там не был |

`link` (связь без уточнения) остался от E1 — в файле героя он **запрещён**, выбери тип.

### Источник (у каждой записи)

| `source` | Что | Ещё |
|---|---|---|
| `bio` | официальная биография | `url` не нужен |
| `liquipedia` | Liquipedia | `via`: `infobox` (поле инфобокса), `lore` (текст лор-страницы), `place` (герой лишь упомянут на странице места); `url` — обязательно, из `meta.json` |
| `comic:<id>` | официальный комикс из `content/media.json` | комикса там нет — запиши в `unconfirmed` |
| `ours` | наше решение, прямо в лоре не сказано | `note` обязательна — почему так |

### Путь (`path`)

Остановки `{ "place": … }` или `{ "region": … }` в хронологическом порядке; стрелка на карте — от остановки к следующей. Каждая остановка — место из твоих `links`, не `mention`; две одинаковые подряд нельзя, вернуться в прежнее место можно. Нет перемещения — нет `path`.

### Связи героев (`relations`)

`"hero"` — **key** другого героя, `"type"` — кем **тот** герой приходится **этому**:

| `type` | | `type` | |
|---|---|---|---|
| `ally` | союзник | `mentor` | его наставник (обратная — `student`) |
| `enemy` | враг | `student` | его ученик |
| `rival` | соперник | `master` | его хозяин, господин (обратная — `servant`) |
| `family` | родня | `servant` | его слуга, подчинённый |
| `love` | возлюбленный | | |

Отдельная реплика озвучки (подколка, шутка, фраза при убийстве) — **не основание** для связи: нужна запись в инфобоксе (`family`, `heroes`), текст лор-страницы или биография. Такие реплики — в `unconfirmed` (решение партии 01, #46).

Пример: X — наставник героя → в файле героя `{ "hero": "<key X>", "type": "mentor" }`, в файле X — `{ "hero": "<key героя>", "type": "student" }`. `place` — где связь проявилась, если сказано. Источник — как у мест.

### Кандидаты в места (`candidates`)

Место из лора, которого нет в `regions.json`: `name` (как в источнике, по-английски), `region` — предполагаемый регион, `event`, `source` (+ `url`), `note` — почему этот регион. **На карту не добавляй** — решение примет владелец в #59. Если у героя других мест нет, в `links` оставь `uncharted` с `note`, где назван кандидат.

## 3. Как помечать неуверенность

- Есть источник, но толкование спорное — запись оставь и добавь `"doubt": "что под сомнением и почему"`.
- Источник противоречит другому — запиши вариант по биографии, другое — в `doubt`.
- Не нашёл подтверждения — **не записывай** связь, а опиши в `unconfirmed`.
- Наше решение без прямого текста — `source: "ours"` и `note`.
- Родина по народу (о самом герое места нет, но родина его народа есть на схеме) — `origin`, `source: "ours"`, `note` и `doubt` (так Alchemist → Home of the Keen Folk, #46).

## 4. Чего не делать

- **Не копировать тексты.** Биографии Valve и тексты Liquipedia (CC BY-SA) не переносим даже частично: всё — своими словами, без цитат. Проверка ловит 8 слов подряд из источника в `summary`, `note`, `doubt`, `unconfirmed`, но и близкий пересказ фразы за фразой — тоже нельзя.
- **Не добавлять места на карту** и не править `regions.json`, `map/layout.json`, `content/` — только кандидаты.
- **Не править чужие файлы** — только `research/e14/heroes/<key>.json`.
- **Не ходить в сеть** и не брать другие сайты (Fandom, форумы): только кэш и справочники.
- **Не выдумывать**: нет в источнике — нет в файле.
- В русском тексте имена героев — латиницей, как в `heroes.json` (Witch Doctor); личные имена персонажей — кириллицей (Райлай, Трездин). В `en` — ни одной кириллической буквы.

## 5. Проверка

```bash
python research/e14/check.py <key>
```

`OK` — готово. Ошибки исправь и запусти снова. Главный агент потом сольёт файлы партии:

```bash
python research/e14/check.py --merge <key> <key> ...   # → research/e1/hero-places.json, place-candidates.json
python research/e1/build.py && npm run check
```
