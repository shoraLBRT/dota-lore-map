# Архитектура

Решения, обязательные для всех, кто пишет код. Функциональные требования — в [SPEC.md](SPEC.md). Изменить решение можно только правкой этого файла в отдельном PR с объяснением.

## A1. Стек

| Что | Решение |
|---|---|
| Сборка | Vite, статический сайт без бэкенда |
| UI | React 18 + TypeScript (`strict: true`), без UI-библиотек |
| Стили | CSS Modules + CSS custom properties (токены из дизайн-системы, `src/styles/tokens.css`) |
| Состояние | React context + `useReducer` для навигации; без Redux/Zustand |
| Анимации | CSS transitions / Web Animations API; без анимационных библиотек |
| Частицы | `<canvas>` поверх карты, свой небольшой движок |
| Тесты | Vitest + @testing-library/react (jsdom) |
| Линт | ESLint (typescript-eslint, react-hooks) |
| Node | 22 LTS, npm |

## A3. Данные

- **Источник правды** — JSON в `research/e1/`, `content/`, `map/`. Приложение их напрямую не читает.
- `npm run data` (`scripts/build-data.mjs`) сливает их в **один** файл `src/data/world.generated.json` и валидирует. Файл коммитится, чтобы сборка не зависела от скриптов.
- Отсутствующий контент (нет описания, нет позиции на карте) — не ошибка: приложение просто не показывает блок или маркер. Ошибка — ссылка на несуществующий регион, место или героя.
- Каждый текст `{ ru, en }` — оба языка непустые, в `en` нет кириллицы (иначе это забытый перевод) — ошибка `build-data.mjs`. Словари `src/i18n/*.json`: одинаковые ключи и переменные `{…}`, в `en.json` нет кириллицы — проверяет `i18n.test.ts`.
- Тексты — объекты `{ "ru": "...", "en": "..." }`. Тип в TS: `Localized`.
- В русских текстах названия героев пишутся латиницей, точно как в `research/e1/heroes.json` (как в русском клиенте игры); личные имена персонажей — кириллицей.

### Формат `content/regions/<regionId>.json`
```jsonc
{
  "id": "icewrack",
  "subtitle": { "ru": "...", "en": "..." },
  "biome": "snow",               // snow | forest | jungle | desert | mountains | plains | swamp | sea | islands | volcanic | city | sky | void | hell | fog
  "ambient": { "type": "snow", "density": 0.6 },   // snow | ash | embers | fog | rain | sparkles | stars | leaves | sand | none
  "traits": {
    "rule":  { "ru": "...", "en": "..." },
    "magic": { "ru": "...", "en": "..." },
    "biome": { "ru": "...", "en": "..." }
  },
  "description": { "ru": "...", "en": "..." },
  "media": ["icewrack-new-neighbors"],   // необязательно: id из content/media.json, ≤ 3
  "places": {
    "<Place name из research/e1/regions.json>": {
      "name": { "ru": "...", "en": "..." },
      "type": { "ru": "...", "en": "..." },
      "description": { "ru": "...", "en": "..." },
      "media": ["frostreach-the-dragon"]   // необязательно, ≤ 3
    }
  }
}
```
Сторона (`side`) и название региона берутся из `research/e1/regions.json`.

Необязательное поле `"moreLink": "https://…"` — ссылка «Подробнее ↗» в панели региона (SPEC §5.4 п. 6); только `https://`. Медиа (`media` у региона и места — список id из `content/media.json`) и шапка места (`art`) панель показывает, если они есть. Клик по карточке медиа ставит `?media=<id>` (A5).

### Формат `content/media.json`
Медиа галереи (SPEC §5.6, §10) — один файл на весь мир; регион и место ссылаются на медиа по `id` (поле `media` выше), поэтому одно медиа можно показать в нескольких местах.
```jsonc
{
  "note": "...",
  "media": [
    {
      "id": "frostreach-the-dragon",          // kebab-case, уникален
      "type": "image",                        // image | youtube
      "src": "https://cdn.steamstatic.com/...",   // только у image: https-ссылка или относительный путь к ассету;
                                              // или { "ru": "...", "en": "..." }, если у картинки есть версии на двух языках
      "youtubeId": "xxxxxxxxxxx",             // только у youtube: 11 символов, встраивание через youtube-nocookie.com
      "excerpt": true,                        // необязательно, только у image: картинка — одна страница комикса,
                                              // целиком он по sourceUrl (метка «отрывок», кнопка «Читать комикс целиком ↗»)
      "title":       { "ru": "...", "en": "..." },
      "subtitle":    { "ru": "Комикс", "en": "Comic" },   // тип: Комикс | Синематик | Арт | Трейлер
      "description": { "ru": "...", "en": "..." },         // необязательно
      "credit": "Valve Corporation",          // правообладатель (SPEC §15)
      "sourceUrl": "https://www.dota2.com/..."   // страница источника, https
    }
  ]
}
```
- Только официальные материалы Valve (SPEC §11.2): комиксы и страницы dota2.com, синематики и трейлеры с YouTube-канала Dota 2, официальный арт. Каждая ссылка проверяется вручную перед добавлением; сомнительное не добавляем. Тексты — свои слова.
- Арт карточек Artifact (Valve) — разрешён как медиа (решение владельца 2026-11-17, #114): картинка карточки с CDN Valve по прямой https-ссылке (`src: { ru, en }`, есть русская версия), `sourceUrl` — страница Artifact в Steam, ≤ 3 на регион или место, и только у места или региона, чьё название стоит на карточке. Источником лора Artifact не служит: в описании — что на картинке, без фактов о месте.
- Страницы комиксов с текстом даём на языке интерфейса: `src: { ru, en }` (проверено, что русская страница на CDN есть и отличается от английской); нет русской версии — `src` строкой, показывается английская. Выбор — `mediaSrc(m, lang)` в `src/data/world.ts`.
- Картинки в репозиторий не копируем: `src` — прямая ссылка на CDN Valve (как портреты в A6). Нет прямой официальной ссылки — медиа не добавляем.
- Комикс в галерее — одна страница плюс явная ссылка на весь комикс (решение владельца 2026-11-11, #7): у таких медиа `"excerpt": true`. Страница — не обязательно первая (берётся самая показательная), поэтому метка — «отрывок», а не «страница 1 из N».
- Ссылка на источник открывается на языке интерфейса: у `www.dota2.com` к `sourceUrl` добавляется `l=russian|english` (`mediaSourceUrl(m, lang)`, как у страниц героев в A6); остальные источники — как есть.
- Ошибка: неизвестный `id` в ссылке, больше 3 медиа у региона или места, повтор id, нет ни `src`, ни `youtubeId`, `src` у видео или `youtubeId` у картинки, `excerpt` не `true` или не у картинки, `http://` в `src`/`sourceUrl`, нет `credit`, неполный перевод. Предупреждение: медиа ни к чему не привязано.
- В `world.generated.json`: `World.media` (все медиа), `Region.media` и `Place.media` — списки id. Нет медиа — поля нет.

### Формат `research/e1/hero-aliases.json`
Алиасы для поиска героя (SPEC §6.5) — отдельно от `heroes.json`, потому что тот повторяет официальный список Valve, а алиасы — наши словарные данные.
```jsonc
{ "note": "...", "aliases": { "<hero key>": ["Пудж", "Butcher", "Мясник"] } }
```
- Что кладём: кириллическое написание имени, общеизвестные сокращения и прозвища сообщества (`CM`, `КМ`, `Войд`), личные имена персонажей (`Rylai`, `Райлай`). Сомнительное не добавляем.
- Сравнение без учёта регистра, `ё`/`е` и лишних пробелов (`normalizeAlias` в `scripts/build-data.mjs`); поиск в приложении нормализует так же.
- Ошибка: неизвестный ключ героя, пустая строка, повтор внутри героя, совпадение с именем героя. Предупреждение: один алиас у нескольких героев. Проверяют и `build-data.mjs`, и `build.py`.
- В `world.generated.json` — поле `Hero.aliases` (нет алиасов — поля нет).

### Формат `research/e1/hero-places.json` — модель связей (E14, #45)
Где герой бывал и что там делал, его путь и связи с другими героями. Герой — по имени из `heroes.json`; другие герои в связях — по `key`.
```jsonc
{
  "_legend": { ... },
  "heroes": {
    "<имя героя>": {
      "links": [                                   // ≥ 1; места по хронологии — по этому порядку идут места героя и нити (A11)
        {
          "place": "Turstarkuri",                  // имя места из regions.json — или "region": "<id>" (регион целиком); ровно одно
          "event": "origin",                       // тип события, см. ниже
          "source": "liquipedia",                  // bio | liquipedia | comic:<id медиа> | ours
          "via": "infobox",                        // только у liquipedia: infobox | lore | place
          "url": "https://liquipedia.net/dota2/…", // необязательно; https, у liquipedia — liquipedia.net/dota2/
          "note": "…",                             // необязательно, по-русски; обязательно у region "uncharted"
          "doubt": "…"                             // необязательно: что под сомнением и почему
        }
      ],
      "path": [{ "place": "Turstarkuri" }, { "place": "Tyler Estate" }],   // необязательно, ≥ 2 остановок
      "relations": [{ "hero": "invoker", "type": "enemy", "place": "…", "source": "bio" }],   // необязательно
      "profile": {                                 // необязательно, для профиля героя (E15)
        "summary": { "ru": "…", "en": "…" },       // ≤ 500 знаков на язык, своими словами
        "art": ["https://cdn.cloudflare.steamstatic.com/…"]   // только официальные ссылки Valve (A6)
      }
    }
  }
}
```
- **Типы события** (`event`) и когда какой:

  | `event` | Значение |
  |---|---|
  | `origin` | родина: родился, вырос, отсюда его народ или род; у пришельцев — родной план |
  | `home` | живёт или базируется сейчас |
  | `journey` | путь или переезд: пришёл сюда из другого места |
  | `battle` | сражение или нападение: бился, напал, разорил, осаждал |
  | `service` | служба: служил, правил, охранял, состоял в ордене, учился |
  | `exile` | изгнание или заточение: изгнан отсюда или заточён здесь |
  | `death` | гибель или перерождение: погиб, убит, превращён, воскрес |
  | `visit` | бывал, без важного события |
  | `mention` | место только упомянуто рядом с героем (предмет, реплика, слух), сам он там не был |

- **Одно место — одна связь.** Несколько событий в одном месте — берётся главное по порядку `origin` → `home` → `exile` → `battle` → `death` → `service` → `journey` → `visit` → `mention`, остальное — в `note`. Нет мест в лоре — `region: "uncharted"` с `note` (В1).
- **Источник** у каждой записи (`links`, `relations`, кандидаты): `bio` — официальная биография dota2.com; `liquipedia` — Liquipedia, `via` уточняет где: `infobox` (поле инфобокса лор-страницы `<Герой>/Lore`), `lore` (текст лор-страницы), `place` (герой лишь упомянут на странице места — самая слабая связь, в таблицах E1 — `†`); `comic:<id>` — официальный комикс из `content/media.json`; `ours` — наше решение, прямо в лоре не сказано (`*`). Тексты — своими словами, без цитат.
- **Путь** (`path`) — остановки `{ place }` / `{ region }` в хронологическом порядке; стрелка — от остановки к следующей, значок — `event` связи с местом, куда ведёт стрелка. Каждая остановка — место из `links` героя, не `mention`; одинаковые остановки подряд нельзя, вернуться можно. Нет перемещения — нет поля.
- **Связи героев** (`relations`): `hero` — key другого героя, `type` — кем **тот** приходится **этому**: `ally`, `enemy`, `rival`, `family`, `love` (симметричные), `mentor` ↔ `student`, `master` ↔ `servant` (парные). `place`/`region` — где связь проявилась, необязательно. Пара `hero` + `type` не повторяется; два героя не могут быть оба `mentor` (или `master`) друг другу — ошибка.
- **Миграция E1 → E14** (без потерь, таблицы `docs/research/E1-places.md` не изменились): `role` → `event` (`origin`, `home`, `link`; `link` уточнён партиями E14 и убран из модели в #115); `basis: bio` → `source: bio`; `infobox` → `liquipedia` + `via: infobox`; `page` → `liquipedia` + `via: place`; `ours` → `ours`.
- **Правила модели — только в `build-data.mjs`** (#115): он проверяет `hero-places.json`, `regions.json` (`tier`/`side`/`sideBasis`, одна столица, `placement`), «каждый герой из `heroes.json` привязан» и, с ключом `--check-hero <файл>…`, файлы героев E14 строже (`url` у Liquipedia, `note` у `ours`); `research/e14/check.py` вызывает его через `node`, `--merge` — `build-data.mjs --check --hero-places <файл>`. `build.py` — только отчёт `docs/research/E1-places.md` и проверка `place-candidates.json`.
- **Ошибка** (`build-data.mjs`): неизвестный ключ в записи, неизвестное место, регион, герой или медиа, не ровно одно из `place`/`region`, повтор места в `links`, неверный `event`/`source`/`via`/`type`, `via` не у Liquipedia, не-https `url`, остановка пути не из `links` или `mention`, путь из одной остановки, `summary` без перевода, с кириллицей в `en` или длиннее 500 знаков, арт не с хоста Valve (`www.dota2.com`, `*.steamstatic.com`, `steamcdn-a.akamaihd.net`).
- **Значимость места** (#68, #115) — `Place.significance` в `world.generated.json`, считает `placeSignificance` в `build-data.mjs` по связям всех героев с местом, два уровня: `event` — есть связь с событием не из `OFF_PATH_EVENTS` (`mention`), место — остановка чьего-то `path`, у места есть `media` или место — столица; иначе `minor` — только `mention` или связей нет. Нет поля (старые данные, тесты) — как `event`. Связь с регионом целиком на места не влияет. Список `OFF_PATH_EVENTS` совпадает с `OFF_PATH` нитей (`threads.ts`, A11) — проверяет `build-data.test.mjs`: место события и остановка пути — одно и то же понятие. Новые связи подхватываются при `npm run data`, ручной разметки нет. Вид — SPEC §6.3: класс `event` / `minor` у маркера, `data-significance`; кольцо 9 / 7 px, точка 4 / 3 px, подпись 13 / 12 px; цвета `--marker-event`, `--marker-minor` (≥ 3:1 к `--bg-0…2`, проверяет `quality.test.ts`).
- В `world.generated.json` — `Hero.links` (`{ regionId, placeSlug?, event, source, via?, url?, note?, doubt? }`), `Hero.path` (`{ regionId, placeSlug? }[]`), `Hero.relations` (`{ hero, type, regionId?, placeSlug?, source, … }`), `Hero.profile`; нет данных — поля нет. Интерфейс использует места, их порядок, `event` и `path` — нити со стрелками и значками (A11, #67); `relations` и `profile` — профиль героя (A15).

### Формат `research/e1/place-candidates.json`
Места из лора, которых нет на схеме мира. В партиях E14 на карту не добавляются — решение в #59. В приложение не попадают, поэтому проверяет их только `build.py`.
```jsonc
{ "note": "...", "candidates": [
  { "name": "Arktura", "hero": "witch_doctor", "region": "<предполагаемый регион>", "event": "origin",
    "source": "bio", "url": "…", "note": "почему этот регион", "doubt": "…" }
] }
```
Ошибка: название совпадает с местом на схеме (регистр и лишние пробелы не важны) — значит, это связь `links`; неизвестный регион или герой; нет героя; неверный `event`; у `liquipedia` нет `url`; пара `name` + `hero` повторяется.
- **Решение по кандидату** (#59): на схему — если есть событие героя не `mention` из `bio`, `liquipedia` + `lore` или `comic:<id>`, а регион следует из источника или из соседнего места схемы; объединить — если место лежит внутри уже нанесённого (уходит в `note` связи); иначе кандидат остаётся в файле отклонённым до нового источника. Регион, которого источник не называет, не угадываем.

### Исследование героев E14 (`research/e14/`)
- `fetch.py <key> …` — кэш источников в `research/e14/cache/<key>/` (в `.gitignore`, не коммитится): биография dota2.com RU/EN (`datafeed/herodata`, поле `bio_loc`) и вики-текст `<Герой>/Lore` и `<Герой>` одним запросом к API Liquipedia (`action=query`, не `parse`). Строго по очереди, пауза 2,5 с между любыми запросами, User-Agent проекта (CLAUDE.md), без потоков.
- `heroes/<key>.json` — результат исследователя по `template.json`, инструкция — `README.md`. Та же модель, что в `hero-places.json`, плюс `hero`, `read` (что прочитано, минимум обе биографии), `candidates` (без `hero`), `unconfirmed`. Строже: у `liquipedia` нужна `url`, у `ours` — `note`, `profile.summary` обязателен; тексты исследователя (`summary`, `note`, `doubt`, `unconfirmed`) не повторяют источник из кэша 8 словами подряд.
- `check.py [<key> …]` — машинная проверка файлов; `check.py --merge <key> …` — проверить и заменить запись героя в `hero-places.json` и его кандидатов в `place-candidates.json` (ничего не пишет, если после слияния есть ошибки). Тесты — `test_e14.py` (в `npm run check`).

### Формат `map/layout.json`
Координаты нормированы: `x, y ∈ [0, 1]` относительно картинки мира; мир квадратный (`aspect: 1`, SPEC §4, #163).
```jsonc
{
  "aspect": 1,                         // ширина к высоте; ярусы — полигоны в углах, полос (bands) нет
  "regions": {
    "<regionId>": {
      "polygon": [[x, y], ...],          // замкнутый контур, без самопересечений
      "label": [x, y],                   // якорь названия и подсказки
      "camera": { "x": 0.2, "y": 0.3, "zoom": 3 }   // центр кадра и масштаб при приближении
    }
  },
  "places": { "<Place name>": { "pos": [x, y] } }
}
```
- `camera.zoom = z`: слой мира увеличен в `z` раз (по высоте кадра видно `1/z` мира); центр — середина габарита региона, `frameCamera` не уводит кадр за картинку.
- Соседние регионы на суше делят границу (общие вершины), полигоны не пересекаются; места — внутри полигона своего региона, между местами одного региона ≥ 0.012. Проверка — `node map/check-layout.mjs`, схема — `node map/render-schema.mjs` → `docs/map/schema.svg` (подробности — [map/README.md](map/README.md)).

## A4. Карта и камера

- Один слой карты `MapStage`: картинка мира (`WorldArt`, A10) + SVG-оверлей в той же системе координат. Пропорции слоя — `world.aspect` из `map/layout.json` (мир квадратный, SPEC §4): `viewBox="0 0 1600 1600"` (`STAGE_WIDTH × STAGE_HEIGHT`, высота = 1600 / aspect), CSS-переменная `--aspect` у слоя. Слой **покрывает** кадр (`width: max(100cqw, 100cqh·aspect)`, по центру flex, #165): zoom 1 — мир во весь кадр, пустоты вокруг арта нет.
- Поверх арта полигоны регионов прозрачные и без контура (`fill-opacity: 0`, `stroke: none`) — это только зоны клика; при выбранном герое приглушают регионы (`fill-opacity: 0.6`); без арта — заглушка цветом биома.
- Подсветка и вуаль (#188): кривая через точки полигона (`smoothPath`, Catmull-Rom). S1h — свечение изнутри (ступени широкой обводки под `clipPath` региона, без фильтров) и контур `vector-effect: non-scaling-stroke` ≤ 2 px экрана. S2/S3 на арте — вуаль: размытая копия арта и затемнение вне региона под маской с растушёванной кривой; области фильтров и маски — вся сцена (`userSpaceOnUse`), а не габарит региона. Фокус от тапа подсветки не даёт. Движение подсветки (#211) — только `opacity`: группа подсветки проявляется за `--dur-hl-in` и гаснет за `--dur-hl-out`, пока горит — «дышит» только свечение (не контур) от 1 до `--hl-breathe-min` за `--dur-breathe`; погасшая подсветка держит дыхание на паузе (`animation-play-state`), чтобы угасание шло без скачка. Reduced motion — без дыхания, `--dur-hl-*` = 0.
- Камера — CSS `transform: translate() scale()` на слое карты, анимация через Web Animations API. Длительности — из SPEC §7.1.
- Заглушка арта: полигоны регионов, залитые цветом биома, с текстурой через SVG-фильтр `feTurbulence`. Позволяет делать всё приложение до готовности арта (E2).
- **Подписи — экранный слой (#180).** Названия регионов и маркеры мест с подписями — не в слое карты, а в соседнем `div.screen` (`screenRef`, SVG `data-screen-layer`) над ним: та же рамка, что у слоя карты при zoom 1 (абсолютный ребёнок flex-кадра встаёт по центру, как слой). Слой карты с `will-change: transform` браузер растрирует один раз и при зуме растягивает — текст в нём мылится. Экранный слой камерой **не масштабируется** (#231): смена масштаба предка заставляет Blink заново раскладывать и растрировать каждый текст под ним. Группы с якорем `data-at="x y"` (единицы сцены) ставит в их точки под камерой `placeAnchors` (`screenAnchors.ts`): `translate(точка) scale(S)`, `S` — экранные px (`1600 / ширина слоя`, × `data-k`) или единицы сцены (`data-at-zoom`, × zoom); атрибут `transform` у таких групп React не пишет. Вызовы: `useFreeCamera` на каждом кадре жеста, `useCamera` после каждого рендера. Перелёт: группы сразу в точках нового кадра, сам слой летит WAAPI от `cameraTransform(откуда) cameraInverse(куда)` к `none` — в такт со слоем карты. SVG слоя группы за своим боксом не обрезает (`overflow: visible`). Новый текст на карте — только в экранный слой. Экранный слой мышь не ловит, кроме маркеров (`pointer-events: auto`).
- Слои SVG карты сверху вниз: заливка подсветки S1h (`aria-hidden`, без событий мыши) → полигоны-кнопки; над ними экранный слой: маркеры мест → названия регионов (`aria-hidden`). Подсветка лежит над всеми полигонами, чтобы светлая граница не пряталась под соседями. Подсветка, подписи ярусов и подсказка — только в мире (S1); в S2/S3 их нет.
- Наведение на полигон — только подсветка; подсказку вызывает наведение на название региона в экранном слое через `TOOLTIP_OPEN_DELAY`: «мышь на названии» — `pointermove` окна над картой (`[data-map-viewport]`, без зажатой кнопки) внутри `getBoundingClientRect` его `[data-label]` с запасом 4 px, а не события `<text>` (цель у SVG-текста — глифы, мышь между буквами и строками «уходила»; названия по-прежнему без событий мыши, клик проходит к полигону) или фокус с клавиатуры на полигоне (#193). Сдвиг или зум камеры (ключ `x|y|zoom` кадра) снимает подсказку по наведению; на зуме мира больше `TOOLTIP_MAX_ZOOM` подсказки нет. Наведение пальцем (`pointerType === 'touch'`) игнорируется — на тач-устройствах подсказки нет, тап сразу открывает регион (SPEC §5.3).
- Подсказка региона (`RegionTooltip`) рендерится порталом в `document.body` с `position: fixed`: у слоя карты есть `transform`, а у экрана мира под интро — `scale`, и оба ломают `fixed` у потомков. Позиция (`placeTooltip`, #193) — у габарита названия региона на экране (`getBoundingClientRect` его `[data-label]`, левая граница — `--rail-width`): снизу, сверху, справа или слева — сторона в окне, не на названии и с наименьшим перекрытием габаритов соседних названий; иначе у якоря `label` с прижатием к краю окна.

### Свободная камера (#165)
- `features/world/freeCamera.ts`: чистые функции (`panBy`, `zoomAt` вокруг точки кадра, `anchorAt`, `centered` — камера со сдвигами → точка в центре всего кадра, `wheelFactor`, `wheelDelta`, `limitWheel`, `decay`) и хук `useFreeCamera`. Жесты — pointer events на кадре: порог перетаскивания 5 px, затем `setPointerCapture`, клик после перетаскивания гасится в фазе захвата; два пальца — щипок вокруг середины; отпустили — инерция (затухание 0.92 за 16 мс). Колесо (`passive: false`), двойной клик по морю, `+`/`−`, стрелки и `0` (keydown на кадре, когда фокус внутри карты) — плавное движение через `requestAnimationFrame` (зум в логарифме, точка под курсором на месте). Reduced motion — сразу на место, без инерции.
- `useCamera` хранит свободную камеру вместе с кадром `shot`, к которому она относится: перелёт к региону, месту или в мир (смена `shot`) её сбрасывает и начинается с того места, куда карту утянули. Transform слоя (и экранного слоя подписей) хук пишет напрямую в каждом кадре анимации, React узнаёт о камере не чаще раза в кадр: `markerScale` и `threadScale` берут текущий zoom, названия регионов — `pxScale` = 1 px экрана в единицах сцены (#189).
- Мир — только названия регионов (#243, вместо смыслового зума #190; SPEC §8.6): маркеров мест в мире нет — их рисует `MarkersLayer` только в регионе и месте; надписи по территории региона под камерой нет. Выход в мир: `useFreeCamera({ onFloor })` зовётся отдалением с нижнего упора, `useCamera` оставляет камеру мира там же (`EXIT_SHOT`) и вызывает `onLeave`.
- Свободная камера выключена в мире со списком регионов (телефон) и во время перелёта. Кнопки — `ZoomControls` справа внизу левее панели, на телефоне скрыты (щипок).
- Окна, которые закрываются кликом мимо (обратная связь, меню языка), слушают тап, а не нажатие: `listenOutsideTap` (`app/outsideTap.ts`) — нажали и отпустили вне окна ближе 5 px, без второго пальца (#182). Перетаскивание и щипок карты окна не закрывают.
- Подсказки мира при первом входе (#181, SPEC §5.3) — `WorldHint.tsx`: `useOnceHint(ключ localStorage)`; сначала `MoveHint` (жест), затем `WorldHint` («выберите регион»). Жест гасит `onCameraMove` (`MapStage` → `useCamera({ onMove })` из `onChange` свободной камеры: любой сдвиг или зум пользователем, перелёты — нет) или открытый регион; пока он виден, наведение на регион строку «выберите регион» не гасит. Ввод — `TOUCH_QUERY`, не ширина окна.
- Колесо и щипок над подсказками карты (`data-map-tip`, порталы в `body`) — зум камеры, а не страницы (#208): `useFreeCamera` слушает `wheel` на документе (обычное колесо листает раскрытую подсказку, если есть куда), в Safari — `gesture*` на кадре и подсказках. Иначе щипок тачпада масштабирует всю страницу, и подсказка растёт вместе с картой.

### Регион и место (S2/S3)
- Правая панель лежит **поверх** карты (`position: absolute` у правого края), а не рядом с ней: свернуть и развернуть её можно без смещения карты (SPEC §5.4). Ширина — токен `--panel-width`, сколько кадра она закрывает — `--panel-inset` (в px, его читает JS; на узком экране `0px`).
- Камера региона и места кадрирует свободную часть кадра (без панели и шторки) — `regionFrame(рамка полигона, view, место?)` (#192): центр — середина рамки, zoom — `REGION_FILL` 0.7 × min(свободная ширина / ширина рамки, свободная высота / высота рамки) в px слоя, в [1, `REGION_ZOOM_MAX`]; место — центр кадра на месте, zoom × `PLACE_ZOOM`. `frameCamera` остался для камеры мира (и `layout.camera` без рамки): zoom от мира, вписанного в кадр (`containScale`), ужатый в (ширина кадра − панель) / размер вписанного мира раз. Оба дают сдвиг `offset = inset / 2` (px) для `cameraTransform` и в конце прижимает камеру к картинке (`clampCamera`: zoom в [1, `maxZoom`], на арте — видимая часть кадра без панели и шторки, #112: регион у края мира встаёт в свободную часть, под панелью мир может кончиться). Свободная камера в регионе и месте прижимается так же, в мире — весь кадр (`wholeFrame`). Камера мира под открытой панелью — zoom 1, весь кадр на арте, арт уходит под панель (#97 больше не ужимает карту). Без измерений (jsdom) камера та же, что в `layout.json`; `layout.camera` теперь — только ключ перелёта и рамка арта региона. Потолки зума — константы `camera.ts` в долях «мир целиком» (#179): предел любой камеры `FREE_ZOOM_MAX` = 3 (`maxZoom` — меньшее из него, разрешения арта и `view.zoomMax`), кадр региона `REGION_ZOOM_MAX` = 2.5 (`regionFrame`, у камеры места — ×`PLACE_ZOOM`); `layout.camera` их не знает. Уровни зума свободной камеры (#209, SPEC §8.6) — `zoomLevels(рамки регионов, view, рамка региона?)`: мир — [1, `WORLD_SHARE` 0.93 × медиана `regionFrame` всех регионов на измеренном кадре с панелью и шторкой], регион и место — [min(потолок мира, кадр региона), кадр региона × `REGION_ZOOM_IN` 1.15]; `useCamera` кладёт их в `zoomMin`/`zoomMax` кадра свободной камеры (`roam`), `clampCamera` держит zoom в них, перелёты (`regionFrame`/`frameCamera` по `stage`) — нет. «Весь мир» (кнопка, `0`) в регионе и месте летит к кадру региона. Колесо — константы `freeCamera.ts`: `WHEEL_RATE` 1.2 на 100 px, `wheelDelta` режет событие до `WHEEL_MAX_DELTA` 100 px (строка Firefox — 100/3 px), `limitWheel` — не больше щелчка за `WHEEL_REFILL` 120 мс; `ZOOM_STEP` 1.3. Камера места (#192, вместо полпути к месту #96) — место в центре свободной части, zoom — кадр региона × `PLACE_ZOOM` 1.15 (потолок свободной камеры региона); у края мира `clampCamera` сдвигает центр. Вуаль региона гасит целиком чужие ярусы (`foreignTiers`: верхний и нижний для континента, другой ярус для яруса) — цвет `--bg-0` под маской край растушёван внутрь ступенями обводки в маске (`TIER_FEATHER`, без фильтра — A14). Частицы `AmbientCanvas` с `region` летят в рамке региона на экране (берётся из `getBoundingClientRect` слоя каждый кадр), обрезаны `clip` по `smoothPath` региона, число — `particleCount` от площади рамки.
- Панель кадр учитывает всегда, свёрнута она или нет, — поэтому сворачивание камеру не трогает. Свёрнутая панель раскрывается сама при смене региона или места.
- В S2/S3 полигоны регионов — не кнопки: соседи затемнены (`filter`) и не ловят мышь, активный регион — «пустое место» карты; клик по нему в S3 возвращает в S2 (SPEC §5.1).
- Подписи маркеров (`placeMarkerLabels`) получают видимую часть кадра (`visibleFrame` без панели и шторки) в единицах маркеров: подпись, которая вышла бы за неё, ищет другую сторону или прячется (SPEC §8.6).
- Маркеры мест рисуются в группе с якорем `data-at` (`placeAnchors`, выше): размер маркеров и подписей в экранных пикселях не зависит от приближения и окна; в месте маркеры крупнее в `PLACE_ZOOM` раз (`data-k`).
- A3: названия регионов гаснут в первой трети перелёта и возвращаются в последней, маркеры появляются в последней трети с шагом 40 мс, панель выезжает за `--dur-panel-in` (= `--dur-camera`, кривая `--ease-in-out`, #192). A4: содержимое панели — fade `--dur-fade` по смене ключа. Длительности камеры — токены `--dur-camera` (мир ↔ регион) и `--dur-place` (внутри региона).
- При `prefers-reduced-motion` камера не едет: кадр гаснет и проявляется на новом месте за `--dur-camera`/`--dur-place` (200 мс).

### Подписи на карте (SPEC §8.6, аудит E13)
- Код — `features/world/labels.ts` (чистые функции, тесты `labels.test.ts`), применение — `MapStage`.
- Ширины подписей измеряются в браузере (`getComputedTextLength` по `data-measure`) при смене языка, региона и после `document.fonts.ready`; без измерений (jsdom) — оценка по числу знаков, подписи регионов стоят как в данных.
- Регион: `splitLabel` — длиннее `WRAP_AFTER` = 14 знаков — две строки по пробелу, при котором длинная строка короче всего (`<tspan>`, ярусы — одной строкой).
- Уровни названий (#189, SPEC §8.6): `regionLevels`, `labelMetrics`, `placeRegionLabels` (`labels.ts`), сборка и хук `useRegionNames` — `regionLabelLayout.ts`, знаки гербов — `crests.ts`. Группа названия — `translate(точка label) scale(pxScale)`, внутри всё в px экрана. Пересечение двух рамок на диапазоне зума считается точно (`overlapsOnZoom`: рамки постоянны, точки расходятся линейно); расстановка — раз на кадр, язык и замер, не на кадр зума. Скрытое на этом зуме название — без `data-label` (`data-label-off`): его нет в наведении и подсказке. Регион под мышью, фокусом или пунктом списка в мире (#243) подписан и до порога: `RegionLabels` рисует его название последним — поверх соседей. Без замера кадра (jsdom) видны все. Тест `labels.test.ts` проверяет на 1440×900, 1280×720, 768×1024 и 375×812 (оба языка), что все 27 регионов подписаны до потолка мира и названия не пересекаются.
- Маркеры: `placeMarkerLabels` — жадно, по важности (выбранное место, столица, места выбранного героя, затем по значимости — места событий, обычные, второстепенные (#68, A3); внутри — по порядку данных), в единицах группы маркера (1 = 1 экранный px, не зависит от приближения): справа → слева → сверху → снизу (#191); мешают уже поставленные подписи и фигуры всех маркеров (радиус `ringOf`). Нет места — `hidden` (класс `labelHidden`, подпись видна при наведении, фокусе и у выбранного места); столица и выбранное место (`must`) — на сторону в кадре, где накрывают меньше подписей и колец, иначе справа. Плашки нет (#191): рамка подписи (`labelBox`) — ширина и кегль плюс поля под ореол `LABEL_PAD_X`, `LABEL_PAD_Y`. Подписи региона на экранах 1440×900 и 375×812 считает чистая `markerLabelItems` + `labelBounds` (`markerLayout.ts`), тест — `markerLayout.test.ts` (три самых плотных региона).
- Вид маркера (#191) — `kindOf`: столица — звезда, место события — ромб, второстепенное — точка; фигура меньше зоны нажатия (`HIT_RADIUS` 16 px, на `pointer: coarse` CSS растит до 22 — 44 px). Значок медиа — на углу фигуры в пределах `ring + LABEL_GAP`, подписи его не задевают. Маркер, центр которого за видимой частью кадра, подписи не получает, кроме выбранного места (#96).
- Выбранное место (S3): своя фигура в светящемся кольце 10 px (`--accent-bright`, двойное свечение), подпись — кеглем и шрифтом столицы (`ringOf`/`fontOf` в `markerLayout.ts`).

### Клики во время анимации камеры
SPEC §7.1: анимация камеры не прерывается кликами. `MapStage` на время анимации «занимает» навигацию (`hold()` из `app/navigation.tsx`); все переходы через `open()` — глобус, крошки, Esc, маркеры, регионы — в это время не выполняются, а запоминаются, и после посадки выполняется **последний** запрошенный. Переход извне (кнопка «назад» браузера, ручной адрес) очередь сбрасывает и применяется сразу: камера продолжает с текущего положения (`getComputedStyle(...).transform`).
Пока камера летит (`flying`), подсказки региона и места не рендерятся: их позиция считается от якоря на экране, и посчитанная на старте перелёта оказывается не там (аудит E13). После посадки слой получает кадр, посчитанный по текущему размеру окна, — окно могли повернуть во время перелёта.

### Интро поверх мира
Экран мира рендерится всегда, в том числе на `#/`. Интро (S0) — слой `position: fixed` над ним; экран мира под интро получает `veiled`: размытие `--map-blur` (`backdrop-filter` слоя `.map::after` поверх карты, при A1 гаснет по `opacity`, #185), `scale: 1.08`, `inert` и `aria-hidden`. Так «размытая карта на фоне» — это настоящая карта, и A1 проявляет её без подмены картинки: по «Начать» адрес сразу меняется на `#/world`, с карты снимаются размытие и масштаб (CSS-переход), а интро ещё `--dur-intro` остаётся поверх, пока облака разъезжаются и текст уходит вверх. Длительности JS берёт из токенов (`cssDuration`), поэтому `prefers-reduced-motion` действует и на них.

Кнопка «Начать» включается, когда готовы шрифты дизайн-системы (`document.fonts`) и картинка мира (`WORLD_ART`), но не позже чем через 4 с — медленная сеть не запирает на интро (`features/intro/useWorldReady.ts`).

## A5. Навигация и адреса

Решение по В2 (SPEC §17): **да**, у каждого состояния свой адрес, через hash — работает на GitHub Pages без серверных правил.

| Экран | Адрес |
|---|---|
| Интро | `#/` |
| Мир | `#/world` |
| Регион | `#/r/<regionId>` |
| Место | `#/r/<regionId>/<placeSlug>` |
| Выбранный герой | `?hero=<heroKey>` поверх любого адреса |
| Профиль героя (A15) | `?hero=<heroKey>&profile` — флаг без значения, без `hero` не действует |
| Галерея | `?media=<mediaId>` поверх адреса региона/места или профиля героя (A15) |

`placeSlug` — имя места в kebab-case (`"Tomo'kan"` → `tomokan`).

Галерея (`features/gallery/`): листает медиа экрана, с которого открыта (места или региона); `?media=` с чужим медиа (адрес вручную) показывает его одно, неизвестный id или интро — галереи нет. Открытие карточкой — новая запись в истории; листание и закрытие меняют адрес без новой записи (`navigate(route, { replace: true })`), поэтому «назад» браузера закрывает галерею и не перебирает страницы.

История браузера (#182, SPEC §5.1 «Правила окон»): `navigate` пишет запись через `history.pushState` и кладёт в её `state` адрес, с которого пришли (`dlmPrev`). Переход на адрес прошлой записи — `history.back()`, а не новая запись: Esc и крошки на уровень вверх, закрытие галереи и профиля идут тем же шагом, что «назад» браузера, и история не растёт «место → регион → место». Состояние меняется сразу, адрес — по hashchange; переход, запрошенный до него (два Esc подряд), выполняется после. Закрытие профиля и снятие героя без такой записи — замена (`replace`): закрытое окно «назадом» не возвращается. Запись без `dlmPrev` (первая, ручной адрес) — обычный переход.

Флаг `?nav=new` (#230, SPEC §5.1; прототип до прохода владельцем): читается `navNew()` (`src/app/flags.ts`) из поиска адреса до hash — переходы меняют только hash, флаг держится всю сессию. С ним `open` не переносит героя на новый экран, а `?hero=` без `profile` показывает профиль (чипа нет); Esc снимает героя одним шагом. Раскрытая шторка «Регионы» кладёт запись истории с тем же адресом и пометкой `dlmLayer` (`useBackLayer`, `src/app/backLayer.ts`): «назад» снимает её по popstate без hashchange — шторка сворачивается; свёрнутая иначе — снимает запись `history.back()`. Путь — `PathBar`, шапка окна с × — `WindowHead`, шторка в три положения — `Sheet` с `onClose` (`settleSheet`). Снять флаг — удалить `navNew()` и ветки без него, `Breadcrumbs`, `ProfileCrumb`, `HeroChip`, ромб «Свернуть» и их тесты.

- Облака над миром и прочая атмосфера (#167) — `MapAtmosphere`: один canvas над артом (под частицами и виньеткой) и CSS-слой зерна. Данные — `features/world/atmosphere.ts` в долях мира: облака `SKY_CLOUDS` на трёх высотах (реже над материками, плотнее над морем, у Небес и над Подземьем), туман `FOG_PATCHES` (Неизведанные земли, разлом Глубин, Подземье) и дымка над морем, свечение ярусов `GLOWS` (звёзды Небес, лава — композиция `lighter`). Спрайты рисуются один раз; цвета — токены `--atmo-*`.
- Положение мира каждый кадр — `getBoundingClientRect` слоя камеры: эффекты идут и за жестами, и за WAAPI-перелётом. Облако высоты `d` при панорамировании и приближении движется в `PARALLAX[d]` раз быстрее земли (`project`), туман и свечение лежат на земле. Сила — от приближения (`strength`: весь мир почти чистый, полная при ×4; в регионе облака тоньше, туман своего региона реже); облако шире кадра тает.
- Холст — 0.75 разрешения CSS-px (телефон — 0.5, меньше половины облаков, дрейф 30 кадров/с, без зерна). Reduced motion: без дрейфа, пульса и параллакса, перерисовка только при сдвиге камеры. Замер #167: панорамирование ×2 в Chromium с GPU — 53–56 кадров/с, как без эффектов.
- Путь героя (#168): пока на карте нити (`MapAtmosphere clear`), облака и туман плавно расходятся до `PATH_VEIL` = 0.35 силы (`approachVeil`, reduced motion — сразу): нити лежат в SVG под холстом и иначе тонули бы в облаках.
- Завеса входа в регион (#234, решение владельца 2026-11-21): при переходе мир → регион из центра кадра расходятся `PART_CLOUDS` = 8 облаков (`partCloud`, `atmosphere.ts`), за время перелёта камеры `--dur-camera`; без флага. Reduced motion — без завесы. Прямой заход по адресу региона — без завесы (перелёта нет). Блики на воде отложены, облака по краям кадра отклонены — кода нет ([research/E20-depth.md](research/E20-depth.md)).
- Размытие краёв кадра (#233, решение владельца 2026-11-21): на приближении сверху и снизу кадра — полосы `.dof` (`MapStage`) с `backdrop-filter: blur + brightness` под маской, не на весь экран; лежат над артом и под экранным слоем, поэтому подписи, маркеры, панели и шторки не размыты. Сила `--dof` = `dofAt(zoom)` (0 на мире, полная с ×2.2), её раз в кадр ставит `useDepth`; на мире полосы скрыты (`visibility`). Токены `--dof-*`. Reduced motion — без размытия, только тень (`--dof-shade`). Замер: колесо ×12 и клик по региону в Chromium с GPU (1440×900, 3 прогона) — как без размытия. Флага нет.
- Наклон на приближении (#232, решение владельца 2026-11-21 по #197, SPEC §8.5.2): обёртка слоя карты `.tilt` (`data-tilt`) получает `perspective(p) rotateX(deg)` вокруг центра кадра, `deg = tiltAt(zoom)` — 0° на мире, плавно до `TILT_MAX` = 20° с ×2.5, `p = perspectiveOf(кадр)`; на мире transform пуст (обёртка не 3D-слой). Флага нет. Пишет `useDepth` (`depth.ts` — геометрия): приближение — из inline `transform` слоя (без `getComputedStyle`, его читает только WAAPI-перелёт); MutationObserver на стиле слоя ставит наклон и якоря в том же кадре, что и камеру. Подписи и маркеры остаются в плоском экранном слое: их якоря переносятся в точки наклонённой карты CSS-свойством `translate` (`tiltPoint`). Жесты свободной камеры считают точку под курсором и пальцем через обратную проекцию наклона того зума, к которому идут (`flatAt`, `worldOnScreen`, `pinOnScreen` в `freeCamera.ts`): колесо и щипок держат точку под курсором, перетаскивание — под пальцем. Клики по полигонам и маркерам — обычный hit-test браузера (он учитывает 3D). Под наклоном `getBoundingClientRect` даёт габарит трапеции: облака и туман `MapAtmosphere` берут плоскую рамку слоя (`flatRect`) и ставят центры спрайтов в точки наклонённой карты (холст плоский); частицы региона (`AmbientCanvas`) лежат в своей обёртке `.tiltOver` с тем же наклоном и запасом по краям (иначе у верха кадра — полоса без частиц); подсказки региона и места — `pointOnMap`. Reduced motion — без наклона. Тесты: `depth.test.ts`, `useDepth.test.tsx`, `freeCamera.test.tsx`, e2e `camera.spec.ts` (колесо держит точку, клик попадает в регион и маркер). Раскладка подписей маркеров (`placeMarkerLabels`) считается до наклона — запас мал, но в проверенных кадрах подписи не сходятся. Замер `npm run perf` (Chromium с GPU, 1440×900, 3 прогона, 2026-11-22): с наклоном колесо ×12 — 56–59 к/с, клик по региону — 56–59 к/с, как на сборке main без наклона (57–60 и 56–59); в обоих первый прогон холодный. Камера жеста, ждущая рендера, к новому кадру не пристаёт (`useCamera`): при редких кадрах она откатывала перелёт к региону после колеса.

## A10. Арт карты и предзагрузка

- Адреса арта (`features/world/art.ts`): картинка мира — `WORLD_ART` (`public/art/world-4096.webp`) и превью `WORLD_PREVIEW` (`world-1024.webp`); детальная картинка региона — поле `layout.art` региона (пока пустое). Исходник мира — `map/art/world.jpg` (#163).
- `WorldArt` рисует два HTML `<img>` на весь мир в своём композитном слое (`will-change: transform`) под SVG-оверлеем: превью и поверх него полную картинку, которая проявляется после загрузки и `decode()` (#185); тайлы — SVG в том же слое. Кнопка «Начать» ждёт только превью (`useWorldReady`); `index.html` предзагружает его. Полная картинка вставляется только после `load` страницы и простоя (`app/idle.ts` `afterLoadIdle`) с `fetchpriority="low"` — она не держит первую отрисовку и `load` (#186). `check-budget` считает `dist/art/*.webp` в общем бюджете и ограничивает одну картинку 1.5 МБ.
- Детальная картинка региона — SVG `<image>` под маркерами, покрывает рамку `layout.camera` (1/zoom мира вокруг центра) и проявляется кроссфейдом (`--dur-fade` после `--dur-camera`), когда загружена (`features/world/RegionArt.tsx`). Нет арта — ничего не рисуется.
- **Пирамида тайлов (#164):** `WorldArt` поверх `world-4096.webp` рисует в том же SVG тайлы `public/map/tiles/{z}/{x}_{y}.webp` (`features/world/tiles.ts`), когда на сторону мира приходится больше 4096·1.1 px экрана (ширина слоя × devicePixelRatio): уровень — наименьший достаточный, только тайлы кадра с запасом в полтайла; кадр сверяется с `getBoundingClientRect` слоя камеры раз в 150 мс, тайл проявляется по `opacity` после загрузки. Включает слой манифест `features/world/tiles.json` (`levels` пуст — слоя нет), его пишет `map/art/tiles.mjs pyramid`. `check-budget` считает `dist/map/tiles` отдельно от бюджета до мира: полный уровень по манифесту, тайл ≤ 256 КБ. Скрипты — docs/map/README.md «Плитки арта».
- `preloadImage(url)` грузит картинку через `new Image()` один раз на адрес и никогда не отклоняется (ошибка = «готово»). `preloadRegionArt(region)` вызывается при наведении и фокусе на регион (SPEC §14), картинка мира ждётся кнопкой «Начать».
- Чтобы подключить детальную картинку региона: положить файл в `public/art/`, заполнить `layout.art` с учётом `import.meta.env.BASE_URL`; `scripts/build-data.mjs` должен пропускать поле `art` и проверять, что файл есть.

## A15. Профиль героя (E15, #61)

- Код — `features/hero/`: `profile.ts` (чистые функции `heroMedia`, `heroRelations`, `profilePlaces`), `HeroProfile.tsx` (содержимое панели и крошка `ProfileCrumb`). Вид и поведение — SPEC §6.8.
- **Адрес: `?hero=<key>&profile`** (A5) — `Route.profile`, флаг без значения, пишется только вместе с `hero` (`router.ts`). Выбран герой (`hero`) и открыт профиль (`profile`) — разные состояния: так «назад» и Esc идут по шагам, а переход по карте не теряет героя. Выбрали героя (`pickHere`, поиск, «Связан с») — `hero` + `profile`. `open(screen)` (маркер, регион, крошка, метка «за краем», место из профиля, Esc на уровень вверх) переносит только `hero`: профиль закрыт, видна панель экрана, нити остаются. Крошка профиля и первый Esc — `navigate({ screen, hero })`; второй Esc и ✕ на чипе — `navigate({ screen })`. Галерея открывается и закрывается поверх, флаг не трогает (`closeGallery` убирает только `media`).
- `WorldScreen` рисует `Panel` при открытом регионе **или** открытом профиле; при профиле в панели `HeroProfile`, крошка — `ProfileCrumb`, иначе панель региона или места. Ключ содержимого панели при профиле — `hero/<key>`. `MapStage.panel` — тот же признак, но в мире без свёрнутого профиля: открытая панель уменьшает и сдвигает карту в свободную часть слева от неё (`inset` в мире, кроме телефона со списком регионов, #97), свёрнутая — карта на весь кадр; переход — анимация камеры `--dur-place` (кадр в `useCamera` — камера плюс признак «мир под панелью»). Значки на нитях не встают под панель (`cover`).
- **Чип** (`features/hero/HeroChip.tsx`) — в той же полосе сверху, что и поиск (`HeroBar.module.css`, `.chipBar`): герой выбран, профиль закрыт, поиск закрыт. Кнопка «портрет + имя + Профиль героя» (`data-hero-chip`, имя кнопки — видимый текст) открывает профиль, `DiamondButton` ✕ снимает героя. Высота чипа — `barBottom` → `coverTop` (метки «за краем» ниже).
- **Открыть профиль** — `pickHere` в `WorldScreen`: `navigate({ screen: текущий, hero })`, камера не двигается. Источники: подсказка региона (`MapStage.onPickHero`, #65), портреты `HeroList` в панелях (контекст `HeroPickProvider` / `useHeroPick` в `preview.tsx`; без провайдера портрет остаётся ссылкой на dota2.com), «Связан с» в профиле. Поиск (`pick`) по-прежнему ведёт камеру `heroScreen` (SPEC §6.5).
- **Арты** (`heroMedia`): рендер Valve (A6), затем `profile.art` без портрета, шапки и рендера, затем медиа из источников `comic:<id>` связей и отношений героя. Это `Media` с id `hero-<key>-render` / `hero-<key>-<n>` (у комиксов — свой id). Галерея (`galleryOf`): медиа экрана → медиа героя из `?hero=` → одно медиа по id.
- **Связи** (`heroRelations`): свои `relations` героя и обратные из записей других героев (`RELATION_INVERSE`: симметричные — тот же тип, `mentor` ↔ `student`, `master` ↔ `servant`); своя запись и обратная того же типа — одна строка; порядок — родня, любовь, наставник, ученик, господин, слуга, союзник, соперник, враг, внутри по имени. Заметки исследования (`note`, `doubt`, источник) в интерфейс не выводятся.
- **Места** (`profilePlaces`): есть `path` — остановки по первому появлению, затем остальные места по порядку связей; нет — места по порядку связей. Остановка — то же правило, что у нитей (`OFF_PATH`, A11).
- **Фокус**: профиль открыт или сменился его герой — на `[data-panel-heading]` профиля (имя героя); профиль закрыт и фокус пропал — на заголовок панели экрана, без панели (мир) — на чип. Переход на другой экран — как всегда (`restoreFocus`, A14). Esc — в `App` (A11).
- **Данные** приходят из `research/e1/hero-places.json` через `build-data` (A3) без ручной разметки: новая партия E14 с `profile` и `relations` появляется в профиле после `npm run data`.

## A12. Атмосфера и звук

- Частицы (SPEC §7.3) — `features/atmosphere/`: `particles.ts` — чистая симуляция (параметры видов `SPECS`, `particleCount`, `spawn`, `step`, `twinkle`), `AmbientCanvas` — один `<canvas>` поверх кадра карты в S2/S3 (в мире его нет), тип и плотность — `ambient` региона. Число частиц ∝ плотности и площади кадра (эталон 1280×800), потолок `MAX_PARTICLES` = 220; рисуются только примитивы (круг, линия, эллипс, прямоугольник), туман — заранее нарисованный спрайт с градиентом, свечение углей — ореол вместо `shadowBlur`. `devicePixelRatio` ≤ 2. Цикл — `requestAnimationFrame`, на скрытой вкладке стоит, шаг ≤ 50 мс. Цвета — токены `--particle-*` в `tokens.css`. При `prefers-reduced-motion` канвас не создаётся.
- Звуки (SPEC §7.4) — синтез Web Audio (`src/app/sfx.ts`): наведение (короткий тихий тон), клик, открытие панели (шорох фильтрованного шума и низкий тон), открытие галереи (два тона). Файлов нет — нечего лицензировать и загружать; записанные звуки, если появятся, подключаются заменой `createSynth`.
- `SoundProvider` (`src/app/sound.tsx`) решает, играть ли: звук включён (`localStorage`) и разблокирован. Разблокирует «Начать» или первый жест на любом экране (по прямой ссылке «Начать» нет); `AudioContext` создаётся заранее, в простое после загрузки (`requestIdleCallback`, звук не выключен; иначе — в жесте), и до жеста спит — `play` его будит (#185). «Клик» — один слушатель на `document` для `button`, `a[href]`, `[role=button]`, `[role=option]`; наведение на регион и маркер — `useSfx()` в `MapStage`, не чаще раза в 90 мс; открытие панели — при появлении региона на экране, галереи — при её открытии. Без провайдера `useSfx()` молчит.

Правая панель — нижняя шторка `features/panel/Sheet.tsx`: свёрнута `SHEET_PEEK` = 30 % высоты окна, развёрнута `SHEET_FULL` = 90 %; ручка на всю ширину — тап переключает, «потянуть» (pointer events, `touch-action: none`) меняет высоту, отпустили — встаёт в ближайшее положение; новый регион или место — снова свёрнута. Свёрнутость дока на компьютере к шторке не относится.
- Камера знает о шторке: `View.insetBottom` = 30 % высоты окна, `frameCamera` уменьшает zoom, если рамка региона выше свободной части, и поднимает центр на половину шторки (`offsetY` в `cameraTransform`); метки «нить за краем» считают видимой часть над шторкой.
- Тач: подсказки региона и места открываются только мышью и фокусом (`pointerType !== 'touch'`), тап сразу открывает регион или место; галерея на весь экран и листается свайпом (A5, E6).
- Мир на телефоне — карта во весь экран, список регионов в нижней шторке (решение владельца 2026-11-19, #196; SPEC §13). Камера мира на телефоне — та же свободная камера, что на компьютере (`useCamera`, `useFreeCamera`): особого кадра мира нет, кегли названий — по `labelMetrics(fitted)` (на 375 px первый уровень — 12 px). Жесты пальцем — pointer events в `freeCamera.ts`: один палец — перетаскивание, два — щипок вокруг середины пальцев, двойное касание пустого места (`DOUBLE_TAP_MS`, `DOUBLE_TAP_PX`, не по `[role=button]`, `button`, `a`) — × 2, следующий `dblclick` браузера пропускается; щипок, просивший отдалить за нижний упор уровня в `PINCH_EXIT` раз за жест, зовёт `onFloor` (выход из региона, как колесо, #190). `features/world/RegionList.tsx` — шторка: `<nav>` с ручкой-кнопкой в `<h2>` (`aria-expanded`), пункты в блоке `hidden`, пока свёрнута; `MapStage` рисует её при `regionList` (= телефон и профиль закрыт, `WorldScreen`) только в мире. Развёрнутость — в `WorldScreen` (`regionsOpen`): регион открыт из списка — остаётся развёрнутой, чтобы при возврате фокус встал на пункт (`focus.ts`, `[data-list-region]`), открыт с карты — сворачивается. Пункт — `<button data-list-region>`: нажатие — `onSelectRegion(id, 'list')`, наведение мышью и фокус подсвечивают регион (`listId` в `MapStage`), пока камера летит в мир — шторка прозрачна и не нажимается. Строка-подсказка мира (`WorldHint`) и `ZoomControls` на телефоне не показываются.

## A14. Качество: доступность, производительность, браузеры

SPEC §14, эпик E11.

**Клавиатура.** В мире Tab идёт по полигонам регионов (`role="button"`, `tabindex="0"`, порядок — порядок в `layout.json`), в регионе и месте — по маркерам мест, затем по панели. Enter и пробел открывают, Esc — на уровень вверх (A11 — порядок Esc). Фокус с клавиатуры показывает ту же подсветку и подсказку, что и наведение (A4). Кольцо фокуса полигона — контур подсветки по форме региона, не прямоугольник браузера; фокус от клика, тапа или возврата в мир после действия мышью регион не подсвечивает (#207).
- Фокус не теряется при переходе (`features/world/focus.ts`, вызывается из `WorldScreen` при смене экрана). Если элемент с фокусом пропал, скрыт или перестал быть фокусируемым (полигон в S2 — уже не кнопка, крошки уехали с панелью), фокус ставится: вверх (место → регион, регион → мир) — на маркер места или полигон региона, откуда пришли (на телефоне регион, открытый пунктом списка регионов, — на этот пункт: `WorldScreen` помнит источник, `onSelectRegion(id, 'list' | 'map')`, `restoreFocus(…, { listRegionId })`; пункт прокручивается в видимую часть только внутри списка); вниз и вбок — на заголовок панели (`h2` с `tabindex="-1"` и `data-panel-heading`, без кольца — `[tabindex='-1']:focus` в `global.css`). Фокус, который пользователь держит, не трогаем; `focus({ preventScroll: true })`.
- Окна (галерея, «О проекте», обратная связь) — A8: ловушка фокуса (`components/focusTrap.ts`: с #73 знает поля ввода и фокус на самом окне), возврат на кнопку-источник.
- Подсказка региона в мире (SPEC §6.2, #65) — портал в конце `body`, поэтому порядок Tab ведёт `MapStage`: Tab на полигоне ставит фокус на первую кнопку подсказки, Shift+Tab с первой — на полигон, Tab с последней — `focusAfter` (`features/world/focus.ts`): следующий по порядку Tab элемент после полигона, минуя саму подсказку. Пока фокус в подсказке, она важнее наведения мыши (иначе пропала бы вместе с фокусом). Esc закрывает её и останавливает всплытие, чтобы глобальный Esc (`App`) не снял героя. `mousedown` в подсказке гасится — клик мышью не оставляет в ней фокус. Роль: с кнопками — `group` с именем региона, без героев — `tooltip`.

**Контраст (WCAG AA).** Цвета текста — `--text-1…3`, `--metal-bright`, `--neutral`, `--radiant` — ≥ 4.5:1 на `--bg-0…2`; кольцо фокуса `--accent-bright` ≥ 3:1 (WCAG 1.4.11). Красный `--accent` и тёмный металл — только рамки и заливки, не текст (на `--bg-2` у `--accent` 2.9:1); выбранный язык — светлый текст на `--accent-dim`. Имя ссылки или кнопки с видимым текстом начинается с этого текста (WCAG 2.5.3: «dota2.com: …», «+N: …»). Приглушённый текст (пункты списка регионов без выбранного героя) — цвет `--text-3`, не `opacity` (axe в e2e). Проверяет `src/styles/quality.test.ts` по `tokens.css` и CSS-модулям.

**Картинки.** У каждого `<img>` есть `alt`: портрет-ссылка — `alt=""` (имя у ссылки), портрет без ссылки — имя героя, картинка галереи — название медиа, шапка места — `alt=""` (декор). Проверяет `quality.test.ts`.

**prefers-reduced-motion.** Токены длительностей укорачиваются в `global.css` (A8). Кроме того, каждый CSS-файл с движением — бесконечной анимацией или ключевыми кадрами со сдвигом/масштабом — сам выключает его в `@media (prefers-reduced-motion: reduce)`: панель и шторка появляются без выезда, нить нарисована сразу и не течёт, подсказка и плашка героя без сдвига, медиа галереи без увеличения, карта под интро без масштаба, облака без дрейфа, спиннер без вращения; камера — кроссфейд (A4), частиц нет (A12). Новый файл с движением без такого блока роняет `quality.test.ts`.

**Бюджет загрузки.** До мира грузятся `index.html`, бандл JS и CSS (данные мира внутри бандла) и свои шрифты (A8); портреты и медиа с CDN Valve — только в мире (панели, подсказки, галерея; портреты `loading="lazy"`). `scripts/check-budget.mjs` (часть `npm run check`) считает gzip html/js/css из `dist` и и настоящий размер всех `dist/fonts/*.woff2` (без gzip — woff2 уже сжат) и падает, если бандл > 600 КБ, шрифтов в `dist/fonts` нет или бандл со шрифтами > 3 МБ. Картинка галереи грузится без `lazy` (она видна сразу и обычно — самый крупный элемент) и занимает всю ячейку (`object-fit: contain`), чтобы кадр не прыгал при загрузке.

**Экран ошибки (#107).** `app/ErrorBoundary.tsx` оборачивает `App` в `main.tsx`: исключение при отрисовке — экран «Что-то сломалось» / «Something went wrong» на токенах вместо пустой страницы. Провайдеры могли упасть вместе с приложением, поэтому язык — `detectLang()` (`localStorage`/браузер) напрямую, тексты — в самом компоненте. Кнопки: «Перезагрузить» и «На карту мира» (`#/world` + перезагрузка); ссылка «Сообщить об ошибке ↗» — `feedbackUrl` (A16): сообщение — текст ошибки (имя, сообщение, начало стека, не длиннее 300 знаков), контекст — адрес, экран из `parseHash`, версия, язык. Ошибки в обработчиках событий и асинхронном коде граница не ловит — они не ломают отрисовку.

**Первая отрисовка (#186).** Бюджет: FCP ≤ 1 с, LCP ≤ 1.5 с, CLS ≤ 0.01 (Chrome без троттлинга, холодный кэш); на «Fast 4G» FCP ≤ 2 с. Замер — `npm run perf -- --load [--net 4g] [--url <адрес>]`. Правила:
- `index.html` несёт статичную оболочку интро внутри `#root` (фон — превью мира `<img>`, надпись, заголовок, подзаголовок, место под кнопкой, дисклеймер): она видна до скрипта, React заменяет её первой отрисовкой. Геометрия — как у `Intro.module.css`, токены — из CSS бандла (он блокирует отрисовку). Язык выбирает встроенный скрипт, как `detectLang()`; на глубокой ссылке оболочка без текста. Тексты сверяет со словарями `src/app/bootShell.test.ts` — правишь интро, правь и оболочку.
- Галерея, профиль героя и поиск — отложенные куски (`app/deferred.tsx`), догружаются в простое после `load`; `check-budget` падает, если кусок пропал или попал в первый экран. Основной вес первого экрана — данные мира (кусок `world-*.js`, ~180 КБ gzip).

**Бюджет кадров (#185).** `npm run perf` (`scripts/perf.mjs`, в `check` не входит): боевая сборка, Chromium с GPU, кадры по `requestAnimationFrame`; шаги — вход, колесо ×12, перетаскивание, колесо наружу, клик по региону. Бюджет: 1440×900 — ≥ 57 к/с, p95 ≤ 20 мс, кадр ≤ 50 мс; телефон 375×812 — ≥ 50 к/с. Правила:
- То, что меняется каждый кадр камеры (названия регионов — масштаб группы `pxScale`), не лежит в одном слое с артом и не несёт тяжёлых фильтров: арт — свой слой (A10), ореол подписей — не больше двух `drop-shadow`.
- Не анимировать `filter` больших слоёв: размытие под интро — `backdrop-filter` слоя, который гаснет по `opacity` (A4).
- Дорогие синхронные вызовы — не в жесте, который запускает анимацию: `AudioContext` создаётся в простое после загрузки (A12), будит его `play`.
- Текст на карте (SVG `<text>`) — под предком, чей масштаб на кадре жеста не меняется: смена масштаба предка в Blink — новая раскладка и форма каждой надписи и растр всего слоя заново (#231: −80 % растра и −75 % раскладки на «колесе ×12»). Поэтому экранный слой камерой не масштабируется, на кадре зума у его групп меняется только сдвиг (`placeAnchors`, A4); сдвиг группы — дешёвый путь.
- Анимации появления на элементах, которых много (маркеры), — `animation-fill-mode: backwards`, не `both`/`forwards`: завершённая анимация с заполнением вперёд держит элемент в композиции — по проходу отрисовки (render pass) на маркер на каждом кадре (#231: ~57 проходов на кадр вместо ~4). Конечное состояние — обычный стиль элемента.
- Клик, который открывает экран (регион, место, профиль, «Начать»), — без задач дольше 50 мс (#238). Поэтому: панель рисуется отложенным рендером (`useDeferredValue` маршрута в `WorldScreen`): кадр клика несёт карту — перелёт камеры, вуаль, звук, — а панель и фокус после перехода (`restoreFocus` по ключу показанной панели) приходят следом, React режет её рендер на куски. На пути клика не читать раскладку и стили после записи в DOM: длительности токенов — из кэша `cssDuration` (читается разом при первом вызове, сброс — смена prefers-reduced-motion), `Panel` не прокручивает только что открытую панель (`scrollTo` — принудительная раскладка), сортировка по алфавиту — один `Intl.Collator` на язык, а не `localeCompare` с опциями.
- Новое на кадре камеры проверять трассой, а не догадкой: `scripts/perf.mjs` даёт к/с, разбор — трасса Chromium (`devtools.timeline`, `viz`, `gpu`): пересчёт стилей, раскладка, проверка попадания, растр (`RasterTask`), GPU (`GPUTask`), проходы отрисовки (`DirectRenderer::DrawRenderPass`). Сравнение — с `main` той же сессии на той же машине: разброс между прогонами здесь больше выигрыша.

**Замеры.** Lighthouse (desktop) — `npx lighthouse <url> --preset=desktop` по `npm run preview`: интро, мир, регион, место, галерея, выбранный герой. Цифры последнего замера — в PROJECT_STATE.
- Автоматически (e2e, A7) на всех четырёх проектах: `@axe-core/playwright` на шести экранах (интро, мир, регион, место, галерея, профиль) — нарушений `serious`/`critical` нет; с `reducedMotion: 'reduce'` в мире, регионе и месте после посадки камеры `document.getAnimations()` без бегущих (`running`) анимаций.
- Снимок экрана — `npm run shot -- <адрес> [ШxВ]` (Chromium Playwright, иначе установленный Chrome; dev-сервер 5183, если не запущен — поднимается на время снимка) → `e2e/shots/` (не коммитится). Ширина < 768 — эмуляция телефона.
