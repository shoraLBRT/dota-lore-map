# Архитектура

Решения, обязательные для всех, кто пишет код. Функциональные требования — в [SPEC.md](SPEC.md). Изменить решение можно только правкой этого файла в отдельном PR с объяснением.

## A1. Стек

| Что | Решение |
|---|---|
| Сборка | Vite, статический сайт без бэкенда |
| UI | React 18 + TypeScript (`strict: true`), без UI-библиотек |
| Стили | CSS Modules + CSS custom properties (токены из дизайн-системы, `src/styles/tokens.css`) |
| Состояние | React context + `useReducer` для навигации; без Redux/Zustand |
| Анимации | CSS transitions / Web Animations API; без анимационных библиотек |
| Частицы | `<canvas>` поверх карты, свой небольшой движок |
| Тесты | Vitest + @testing-library/react (jsdom) |
| Линт | ESLint (typescript-eslint, react-hooks) |
| Node | 22 LTS, npm |

## A3. Данные

- **Источник правды** — JSON в `research/e1/`, `content/`, `map/`. Приложение их напрямую не читает.
- `npm run data` (`scripts/build-data.mjs`) сливает их в **один** файл `src/data/world.generated.json` и валидирует. Файл коммитится, чтобы сборка не зависела от скриптов.
- Отсутствующий контент (нет описания, нет позиции на карте) — не ошибка: приложение просто не показывает блок или маркер. Ошибка — ссылка на несуществующий регион, место или героя.
- Каждый текст `{ ru, en }` — оба языка непустые, в `en` нет кириллицы (иначе это забытый перевод) — ошибка `build-data.mjs`. Словари `src/i18n/*.json`: одинаковые ключи и переменные `{…}`, в `en.json` нет кириллицы — проверяет `i18n.test.ts`.
- Тексты — объекты `{ "ru": "...", "en": "..." }`. Тип в TS: `Localized`.
- В русских текстах названия героев пишутся латиницей, точно как в `research/e1/heroes.json` (как в русском клиенте игры); личные имена персонажей — кириллицей.

### Формат `content/regions/<regionId>.json`
```jsonc
{
  "id": "icewrack",
  "subtitle": { "ru": "...", "en": "..." },
  "biome": "snow",               // snow | forest | jungle | desert | mountains | plains | swamp | sea | islands | volcanic | city | sky | void | hell | fog
  "ambient": { "type": "snow", "density": 0.6 },   // snow | ash | embers | fog | rain | sparkles | stars | leaves | sand | none
  "traits": {
    "rule":  { "ru": "...", "en": "..." },
    "magic": { "ru": "...", "en": "..." },
    "biome": { "ru": "...", "en": "..." }
  },
  "description": { "ru": "...", "en": "..." },
  "media": ["icewrack-new-neighbors"],   // необязательно: id из content/media.json, ≤ 3
  "places": {
    "<Place name из research/e1/regions.json>": {
      "name": { "ru": "...", "en": "..." },
      "type": { "ru": "...", "en": "..." },
      "description": { "ru": "...", "en": "..." },
      "media": ["frostreach-the-dragon"]   // необязательно, ≤ 3
    }
  }
}
```
Сторона (`side`) и название региона берутся из `research/e1/regions.json`.

Необязательное поле `"moreLink": "https://…"` — ссылка «Подробнее ↗» в панели региона (SPEC §5.4 п. 6); только `https://`. Медиа (`media` у региона и места — список id из `content/media.json`) и шапка места (`art`) панель показывает, если они есть. Клик по карточке медиа ставит `?media=<id>` (A5).

### Формат `content/media.json`
Медиа галереи (SPEC §5.6, §10) — один файл на весь мир; регион и место ссылаются на медиа по `id` (поле `media` выше), поэтому одно медиа можно показать в нескольких местах.
```jsonc
{
  "note": "...",
  "media": [
    {
      "id": "frostreach-the-dragon",          // kebab-case, уникален
      "type": "image",                        // image | youtube
      "src": "https://cdn.steamstatic.com/...",   // только у image: https-ссылка или относительный путь к ассету;
                                              // или { "ru": "...", "en": "..." }, если у картинки есть версии на двух языках
      "youtubeId": "xxxxxxxxxxx",             // только у youtube: 11 символов, встраивание через youtube-nocookie.com
      "excerpt": true,                        // необязательно, только у image: картинка — одна страница комикса,
                                              // целиком он по sourceUrl (метка «отрывок», кнопка «Читать комикс целиком ↗»)
      "title":       { "ru": "...", "en": "..." },
      "subtitle":    { "ru": "Комикс", "en": "Comic" },   // тип: Комикс | Синематик | Арт | Трейлер
      "description": { "ru": "...", "en": "..." },         // необязательно
      "credit": "Valve Corporation",          // правообладатель (SPEC §15)
      "sourceUrl": "https://www.dota2.com/..."   // страница источника, https
    }
  ]
}
```
- Только официальные материалы Valve (SPEC §11.2): комиксы и страницы dota2.com, синематики и трейлеры с YouTube-канала Dota 2, официальный арт. Каждая ссылка проверяется вручную перед добавлением; сомнительное не добавляем. Тексты — свои слова.
- Страницы комиксов с текстом даём на языке интерфейса: `src: { ru, en }` (проверено, что русская страница на CDN есть и отличается от английской); нет русской версии — `src` строкой, показывается английская. Выбор — `mediaSrc(m, lang)` в `src/data/world.ts`.
- Картинки в репозиторий не копируем: `src` — прямая ссылка на CDN Valve (как портреты в A6). Нет прямой официальной ссылки — медиа не добавляем.
- Комикс в галерее — одна страница плюс явная ссылка на весь комикс (решение владельца 2026-11-11, #7): у таких медиа `"excerpt": true`. Страница — не обязательно первая (берётся самая показательная), поэтому метка — «отрывок», а не «страница 1 из N».
- Ссылка на источник открывается на языке интерфейса: у `www.dota2.com` к `sourceUrl` добавляется `l=russian|english` (`mediaSourceUrl(m, lang)`, как у страниц героев в A6); остальные источники — как есть.
- Ошибка: неизвестный `id` в ссылке, больше 3 медиа у региона или места, повтор id, нет ни `src`, ни `youtubeId`, `src` у видео или `youtubeId` у картинки, `excerpt` не `true` или не у картинки, `http://` в `src`/`sourceUrl`, нет `credit`, неполный перевод. Предупреждение: медиа ни к чему не привязано.
- В `world.generated.json`: `World.media` (все медиа), `Region.media` и `Place.media` — списки id. Нет медиа — поля нет.

### Формат `research/e1/hero-aliases.json`
Алиасы для поиска героя (SPEC §6.5) — отдельно от `heroes.json`, потому что тот повторяет официальный список Valve, а алиасы — наши словарные данные.
```jsonc
{ "note": "...", "aliases": { "<hero key>": ["Пудж", "Butcher", "Мясник"] } }
```
- Что кладём: кириллическое написание имени, общеизвестные сокращения и прозвища сообщества (`CM`, `КМ`, `Войд`), личные имена персонажей (`Rylai`, `Райлай`). Сомнительное не добавляем.
- Сравнение без учёта регистра, `ё`/`е` и лишних пробелов (`normalizeAlias` в `scripts/build-data.mjs`); поиск в приложении нормализует так же.
- Ошибка: неизвестный ключ героя, пустая строка, повтор внутри героя, совпадение с именем героя. Предупреждение: один алиас у нескольких героев. Проверяют и `build-data.mjs`, и `build.py`.
- В `world.generated.json` — поле `Hero.aliases` (нет алиасов — поля нет).

### Формат `research/e1/hero-places.json` — модель связей (E14, #45)
Где герой бывал и что там делал, его путь и связи с другими героями. Герой — по имени из `heroes.json`; другие герои в связях — по `key`.
```jsonc
{
  "_legend": { ... },
  "heroes": {
    "<имя героя>": {
      "links": [                                   // ≥ 1; места по хронологии — по этому порядку идут места героя и нити (A11)
        {
          "place": "Turstarkuri",                  // имя места из regions.json — или "region": "<id>" (регион целиком); ровно одно
          "event": "origin",                       // тип события, см. ниже
          "source": "liquipedia",                  // bio | liquipedia | comic:<id медиа> | ours
          "via": "infobox",                        // только у liquipedia: infobox | lore | place
          "url": "https://liquipedia.net/dota2/…", // необязательно; https, у liquipedia — liquipedia.net/dota2/
          "note": "…",                             // необязательно, по-русски; обязательно у region "uncharted"
          "doubt": "…"                             // необязательно: что под сомнением и почему
        }
      ],
      "path": [{ "place": "Turstarkuri" }, { "place": "Tyler Estate" }],   // необязательно, ≥ 2 остановок
      "relations": [{ "hero": "invoker", "type": "enemy", "place": "…", "source": "bio" }],   // необязательно
      "profile": {                                 // необязательно, для профиля героя (E15)
        "summary": { "ru": "…", "en": "…" },       // ≤ 500 знаков на язык, своими словами
        "art": ["https://cdn.cloudflare.steamstatic.com/…"]   // только официальные ссылки Valve (A6)
      }
    }
  }
}
```
- **Типы события** (`event`) и когда какой:

  | `event` | Значение |
  |---|---|
  | `origin` | родина: родился, вырос, отсюда его народ или род; у пришельцев — родной план |
  | `home` | живёт или базируется сейчас |
  | `journey` | путь или переезд: пришёл сюда из другого места |
  | `battle` | сражение или нападение: бился, напал, разорил, осаждал |
  | `service` | служба: служил, правил, охранял, состоял в ордене, учился |
  | `exile` | изгнание или заточение: изгнан отсюда или заточён здесь |
  | `death` | гибель или перерождение: погиб, убит, превращён, воскрес |
  | `visit` | бывал, без важного события |
  | `mention` | место только упомянуто рядом с героем (предмет, реплика, слух), сам он там не был |
  | `link` | связь из E1 без уточнения типа (бывший `role: link`); остаётся, пока героя не прошла партия E14, в файлах героев E14 запрещён |

- **Одно место — одна связь.** Несколько событий в одном месте — берётся главное по порядку `origin` → `home` → `exile` → `battle` → `death` → `service` → `journey` → `visit` → `mention`, остальное — в `note`. Нет мест в лоре — `region: "uncharted"` с `note` (В1).
- **Источник** у каждой записи (`links`, `relations`, кандидаты): `bio` — официальная биография dota2.com; `liquipedia` — Liquipedia, `via` уточняет где: `infobox` (поле инфобокса лор-страницы `<Герой>/Lore`), `lore` (текст лор-страницы), `place` (герой лишь упомянут на странице места — самая слабая связь, в таблицах E1 — `†`); `comic:<id>` — официальный комикс из `content/media.json`; `ours` — наше решение, прямо в лоре не сказано (`*`). Тексты — своими словами, без цитат.
- **Путь** (`path`) — остановки `{ place }` / `{ region }` в хронологическом порядке; стрелка — от остановки к следующей, значок — `event` связи с местом, куда ведёт стрелка. Каждая остановка — место из `links` героя, не `mention`; одинаковые остановки подряд нельзя, вернуться можно. Нет перемещения — нет поля.
- **Связи героев** (`relations`): `hero` — key другого героя, `type` — кем **тот** приходится **этому**: `ally`, `enemy`, `rival`, `family`, `love` (симметричные), `mentor` ↔ `student`, `master` ↔ `servant` (парные). `place`/`region` — где связь проявилась, необязательно. Пара `hero` + `type` не повторяется; два героя не могут быть оба `mentor` (или `master`) друг другу — ошибка.
- **Миграция E1 → E14** (без потерь, таблицы `docs/research/E1-places.md` не изменились): `role` → `event` (`origin`, `home`, `link`); `basis: bio` → `source: bio`; `infobox` → `liquipedia` + `via: infobox`; `page` → `liquipedia` + `via: place`; `ours` → `ours`.
- **Ошибка** (`build-data.mjs` и `build.py`): неизвестный ключ в записи, неизвестное место, регион, герой или медиа, не ровно одно из `place`/`region`, повтор места в `links`, неверный `event`/`source`/`via`/`type`, `via` не у Liquipedia, не-https `url`, остановка пути не из `links` или `mention`, путь из одной остановки, `summary` без перевода, с кириллицей в `en` или длиннее 500 знаков, арт не с хоста Valve (`www.dota2.com`, `*.steamstatic.com`, `steamcdn-a.akamaihd.net`).
- **Значимость места** (#68) — `Place.significance` в `world.generated.json`, считает `placeSignificance` в `build-data.mjs` по связям всех героев с местом: `event` — есть связь с событием не из `OFF_PATH_EVENTS` (`mention`, `link`), место — остановка чьего-то `path` или у места есть `media`; иначе `link` — есть связь `link` (E1, тип не уточнён) или место — столица; иначе `minor` — только `mention` или связей нет. Связь с регионом целиком на места не влияет. Список `OFF_PATH_EVENTS` совпадает с `OFF_PATH` нитей (`threads.ts`, A11) — проверяет `build-data.test.mjs`: место события и остановка пути — одно и то же понятие. Новые партии E14 подхватываются при `npm run data`, ручной разметки нет. Вид — SPEC §6.3: классы `event` / `minor` у маркера (`link` — без класса), `data-significance`; кольцо 9 / 9 / 7 px, точка 4 / 4 / 3 px, подпись 13 / 13 / 12 px; цвета `--marker-event`, `--marker-minor` (≥ 3:1 к `--bg-0…2`, проверяет `quality.test.ts`).
- В `world.generated.json` — `Hero.links` (`{ regionId, placeSlug?, event, source, via?, url?, note?, doubt? }`), `Hero.path` (`{ regionId, placeSlug? }[]`), `Hero.relations` (`{ hero, type, regionId?, placeSlug?, source, … }`), `Hero.profile`; нет данных — поля нет. Интерфейс использует места, их порядок, `event` и `path` — нити со стрелками и значками (A11, #67); `relations` и `profile` — профиль героя (A15).

### Формат `research/e1/place-candidates.json`
Места из лора, которых нет на схеме мира. В партиях E14 на карту не добавляются — решение в #59. В приложение не попадают, поэтому проверяет их только `build.py`.
```jsonc
{ "note": "...", "candidates": [
  { "name": "Arktura", "hero": "witch_doctor", "region": "<предполагаемый регион>", "event": "origin",
    "source": "bio", "url": "…", "note": "почему этот регион", "doubt": "…" }
] }
```
Ошибка: название совпадает с местом на схеме (регистр и лишние пробелы не важны) — значит, это связь `links`; неизвестный регион или герой; нет героя; `event: link`; у `liquipedia` нет `url`; пара `name` + `hero` повторяется.

### Исследование героев E14 (`research/e14/`)
- `fetch.py <key> …` — кэш источников в `research/e14/cache/<key>/` (в `.gitignore`, не коммитится): биография dota2.com RU/EN (`datafeed/herodata`, поле `bio_loc`) и вики-текст `<Герой>/Lore` и `<Герой>` одним запросом к API Liquipedia (`action=query`, не `parse`). Строго по очереди, пауза 2,5 с между любыми запросами, User-Agent проекта (CLAUDE.md), без потоков.
- `heroes/<key>.json` — результат исследователя по `template.json`, инструкция — `README.md`. Та же модель, что в `hero-places.json`, плюс `hero`, `read` (что прочитано, минимум обе биографии), `candidates` (без `hero`), `unconfirmed`. Строже: `event: link` запрещён, у `liquipedia` нужна `url`, у `ours` — `note`, `profile.summary` обязателен; тексты исследователя (`summary`, `note`, `doubt`, `unconfirmed`) не повторяют источник из кэша 8 словами подряд.
- `check.py [<key> …]` — машинная проверка файлов; `check.py --merge <key> …` — проверить и заменить запись героя в `hero-places.json` и его кандидатов в `place-candidates.json` (ничего не пишет, если после слияния есть ошибки). Тесты — `test_e14.py` (в `npm run check`).

### Формат `map/layout.json`
Координаты нормированы: `x, y ∈ [0, 1]` относительно картинки мира с соотношением сторон **16:10** (`aspect: 1.6`).
```jsonc
{
  "aspect": 1.6,
  "bands": { "upper": [0, 0.13], "abyss": [0.87, 1] },   // полосы ярусов по y
  "regions": {
    "<regionId>": {
      "polygon": [[x, y], ...],          // замкнутый контур, без самопересечений
      "label": [x, y],                   // якорь названия и подсказки
      "camera": { "x": 0.2, "y": 0.3, "zoom": 3 }   // центр кадра и масштаб при приближении
    }
  },
  "places": { "<Place name>": { "pos": [x, y] } }
}
```
- `camera.zoom = z`: кадр 16:10 показывает `1/z` ширины и высоты мира; центр уже ограничен так, чтобы кадр не выходил за картинку.
- Соседние регионы на суше делят границу (общие вершины), полигоны не пересекаются; места — внутри полигона своего региона, между местами одного региона ≥ 0.012. Проверка — `node map/check-layout.mjs`, схема — `node map/render-schema.mjs` → `docs/map/schema.svg` (подробности — [map/README.md](map/README.md)).

## A4. Карта и камера

- Один слой карты `MapStage`: картинка мира (или процедурная заглушка, пока нет арта) + SVG-оверлей в той же системе координат (`viewBox="0 0 1600 1000"`, нормированные координаты × 1600/1000).
- Камера — CSS `transform: translate() scale()` на слое карты, анимация через Web Animations API. Длительности — из SPEC §7.1.
- Заглушка арта: полигоны регионов, залитые цветом биома, с текстурой через SVG-фильтр `feTurbulence`. Позволяет делать всё приложение до готовности арта (E2).
- Слои SVG сверху вниз: подписи (`aria-hidden`) → заливка подсветки S1h (`aria-hidden`, без событий мыши) → полигоны-кнопки. Подсветка лежит над всеми полигонами, чтобы светлая граница не пряталась под соседями. Подсветка, подписи ярусов и подсказка — только в мире (S1); в S2/S3 их нет.
- Наведение = фокус с клавиатуры: оба показывают подсветку и подсказку. Наведение пальцем (`pointerType === 'touch'`) игнорируется — на тач-устройствах подсказки нет, тап сразу открывает регион (SPEC §5.3).
- Подсказка региона (`RegionTooltip`) рендерится порталом в `document.body` с `position: fixed`: у слоя карты есть `transform`, а у экрана мира под интро — `filter`, и оба ломают `fixed` у потомков. Позиция — у якоря `label` региона, с прижатием к краю окна (`placeTooltip`).

### Регион и место (S2/S3)
- Правая панель лежит **поверх** карты (`position: absolute` у правого края), а не рядом с ней: свернуть и развернуть её можно без смещения карты (SPEC §5.4). Ширина — токен `--panel-width`, сколько кадра она закрывает — `--panel-inset` (в px, его читает JS; на узком экране `0px`).
- Камера региона и места кадрирует свободную часть кадра слева от панели: `frameCamera` уменьшает `zoom` из `layout.camera` в (ширина кадра − панель) / ширина слоя раз, сдвигает центр к краю мира, чтобы за картинкой было меньше пустоты, и даёт сдвиг `offset = inset / 2` (px) для `cameraTransform`. Без измерений (jsdom) камера та же, что в `layout.json`.
- Панель кадр учитывает всегда, свёрнута она или нет, — поэтому сворачивание камеру не трогает. Свёрнутая панель раскрывается сама при смене региона или места.
- В S2/S3 полигоны регионов — не кнопки: соседи затемнены (`filter`) и не ловят мышь, активный регион — «пустое место» карты; клик по нему в S3 возвращает в S2 (SPEC §5.1).
- Подписи маркеров (`placeMarkerLabels`) получают видимую часть кадра (`visibleFrame` без панели и шторки) в единицах маркеров: подпись, которая вышла бы за неё, ищет другую сторону или прячется (SPEC §8.6).
- Маркеры мест рисуются в группе `translate(pos) scale(k)`, где `k` переводит единицы SVG в экранные пиксели (`1600 / ширина слоя / zoom`): размер маркеров и подписей не зависит от приближения и окна.
- A3: названия регионов гаснут в первой трети перелёта и возвращаются в последней, маркеры появляются в последней трети с шагом 40 мс, панель выезжает за `--dur-panel`. A4: содержимое панели — fade `--dur-fade` по смене ключа. Длительности камеры — токены `--dur-camera` (мир ↔ регион) и `--dur-place` (внутри региона).
- При `prefers-reduced-motion` камера не едет: кадр гаснет и проявляется на новом месте за `--dur-camera`/`--dur-place` (200 мс).

### Подписи на карте (SPEC §8.6, аудит E13)
- Код — `features/world/labels.ts` (чистые функции, тесты `labels.test.ts`), применение — `MapStage`.
- Ширины подписей измеряются в браузере (`getComputedTextLength` по `data-measure`) при смене языка, региона и после `document.fonts.ready`; без измерений (jsdom) — оценка по числу знаков, подписи регионов стоят как в данных.
- Регион: `splitLabel` — длиннее `WRAP_AFTER` = 14 знаков — две строки по пробелу, при котором длинная строка короче всего (`<tspan>`, ярусы — одной строкой); `clampLabelX` — центр сдвигается так, чтобы подпись целиком была в [8, 1592] единиц SVG. Точки `label` в `map/layout.json` подобраны так, чтобы подписи RU и EN не пересекались на заглушке; под нарисованную карту их раскладывают заново.
- Маркеры: `placeMarkerLabels` — жадно, по важности (выбранное место, столица, места выбранного героя, затем по значимости — места событий, обычные, второстепенные (#68, A3); внутри — по порядку данных), в единицах группы маркера (1 = 1 экранный px, не зависит от приближения): сверху → снизу → справа → слева; мешают уже поставленные подписи и кольца всех маркеров. Нет места — `hidden` (класс `labelHidden`, подпись видна при наведении, фокусе и у выбранного места); столица и выбранное место (`must`) — всегда сверху.

### Клики во время анимации камеры
SPEC §7.1: анимация камеры не прерывается кликами. `MapStage` на время анимации «занимает» навигацию (`hold()` из `app/navigation.tsx`); все переходы через `open()` — глобус, крошки, Esc, маркеры, регионы — в это время не выполняются, а запоминаются, и после посадки выполняется **последний** запрошенный. Переход извне (кнопка «назад» браузера, ручной адрес) очередь сбрасывает и применяется сразу: камера продолжает с текущего положения (`getComputedStyle(...).transform`).
Пока камера летит (`flying`), подсказки региона и места не рендерятся: их позиция считается от якоря на экране, и посчитанная на старте перелёта оказывается не там (аудит E13). После посадки слой получает кадр, посчитанный по текущему размеру окна, — окно могли повернуть во время перелёта.

### Интро поверх мира
Экран мира рендерится всегда, в том числе на `#/`. Интро (S0) — слой `position: fixed` над ним; экран мира под интро получает `veiled`: размытие `--map-blur`, `scale: 1.08`, `inert` и `aria-hidden`. Так «размытая карта на фоне» — это настоящая карта, и A1 проявляет её без подмены картинки: по «Начать» адрес сразу меняется на `#/world`, с карты снимаются размытие и масштаб (CSS-переход), а интро ещё `--dur-intro` остаётся поверх, пока облака разъезжаются и текст уходит вверх. Длительности JS берёт из токенов (`cssDuration`), поэтому `prefers-reduced-motion` действует и на них.

Кнопка «Начать» включается, когда готовы шрифты дизайн-системы (`document.fonts`) и картинка мира (`WORLD_ART`), но не позже чем через 4 с — медленная сеть не запирает на интро (`features/intro/useWorldReady.ts`).

## A5. Навигация и адреса

Решение по В2 (SPEC §17): **да**, у каждого состояния свой адрес, через hash — работает на GitHub Pages без серверных правил.

| Экран | Адрес |
|---|---|
| Интро | `#/` |
| Мир | `#/world` |
| Регион | `#/r/<regionId>` |
| Место | `#/r/<regionId>/<placeSlug>` |
| Выбранный герой | `?hero=<heroKey>` поверх любого адреса |
| Профиль героя (A15) | `?hero=<heroKey>&profile` — флаг без значения, без `hero` не действует |
| Галерея | `?media=<mediaId>` поверх адреса региона/места или профиля героя (A15) |

`placeSlug` — имя места в kebab-case (`"Tomo'kan"` → `tomokan`).

Галерея (`features/gallery/`): листает медиа экрана, с которого открыта (места или региона); `?media=` с чужим медиа (адрес вручную) показывает его одно, неизвестный id или интро — галереи нет. Открытие карточкой — новая запись в истории; листание и закрытие меняют адрес без новой записи (`navigate(route, { replace: true })`), поэтому «назад» браузера закрывает галерею и не перебирает страницы.

## A7. Деплой и проверки

- GitHub Actions: на каждый PR — `npm ci && npm run check`; на push в `main` — сборка и деплой на GitHub Pages (`base: '/dota-lore-map/'`).

Тест, упавший на настоящей ошибке движка, — `test.fixme` со ссылкой на issue `bug`.
- **Коммиты и версии — стандарт [habze](https://github.com/shoraLBRT/habze/blob/main/STANDARD.md)** (#104). PR сливаются только squash; заголовок PR — Conventional Commit на английском, его проверяет обязательная проверка `pr-title / check` (`.github/workflows/pr-title.yml`). Стартовая версия — 0.1.0, история до `bootstrap-sha` в релизы не входит. Обновления зависимостей — Renovate (`renovate.json`, пресет habze).
- Ветка `main` защищена набором правил: слияние только через PR, обязательные проверки `check` (CI) и `pr-title / check`.

## A10. Арт карты и предзагрузка

Цикл — `requestAnimationFrame`, на скрытой вкладке стоит, шаг ≤ 50 мс. Цвета — токены `--particle-*` в `tokens.css`. При `prefers-reduced-motion` канвас не создаётся.

## A13. Адаптив

- Ширины (SPEC §13) — медиазапросы в CSS и `MOBILE_QUERY` (`(max-width: 767px)`, `features/world/camera.ts`) в JS; `useMediaQuery` (`src/app/media.ts`) следит за поворотом и ресайзом.
- ≥ 1280 — основной макет. 768–1279 — панель уже (`--panel-width: 380px`, `--panel-inset: 412px`), по-прежнему поверх карты и сворачивается ромбом.
- < 768 — левая панель — полоса сверху (`--rail-height`), экран — `100dvh`. Кнопки полосы 44×44 px (рекомендация платформ). С кнопкой обратной связи (#73) их 8 — 352 px, поэтому кнопки стоят встык (без `gap` и полей у логотипа и языка), с полями полосы 8 px — 368 px. При ширине < 368 px (360 px) — 40 px в ширину при высоте 44 px и поля 4 px (328 px), < 328 px (320 px) — 38×40 px (312 px). До #73: 7 кнопок с отступами по 4 px, 40×40 px только < 360 px (до #40 последняя кнопка на 320 px вылезала за край на 4 px). 40 px выше WCAG 2.5.8 AA (24 px); убирать кнопку ради 44 px не стали (SPEC §8.6). Правая панель — нижняя шторка `features/panel/Sheet.tsx`: свёрнута `SHEET_PEEK` = 30 % высоты окна, развёрнута `SHEET_FULL` = 90 %; ручка на всю ширину — тап переключает, «потянуть» (pointer events, `touch-action: none`) меняет высоту, отпустили — встаёт в ближайшее положение; новый регион или место — снова свёрнута. Свёрнутость дока на компьютере к шторке не относится.
- Камера знает о шторке: `View.insetBottom` = 30 % высоты окна, `frameCamera` уменьшает zoom, если рамка региона выше свободной части, и поднимает центр на половину шторки (`offsetY` в `cameraTransform`); метки «нить за краем» считают видимой часть над шторкой.
- Тач: подсказки региона и места открываются только мышью и фокусом (`pointerType !== 'touch'`), тап сразу открывает регион или место; галерея на весь экран и листается свайпом (A5, E6).
- Мир на телефоне — список регионов под картой (решение владельца 2026-11-12, #39; SPEC §13). `features/world/RegionList.tsx` рисует `MapStage` с `regionList` (= `useMediaQuery(MOBILE_QUERY)` в `WorldScreen`) только в мире. Кадр карты не меняет размер: `worldListLayout(view, topInset)` (`camera.ts`) считает сдвиг камеры мира — слой 16:10 прижимается к верху кадра (`offsetY` = половина свободной высоты − `topInset`; `cameraTransform` принимает и отрицательный `offsetY`), а если свободной ширины больше (телефон боком) — к левому краю (`offset`); рамка списка — свободная часть кадра (inline style, список `position: absolute` поверх кадра). Поэтому переход мир ↔ регион — обычный перелёт камеры, без скачка размера кадра; виньетка и облака мира кадрируют рамку карты. `topInset` — низ чипа выбранного героя + 8 px (ResizeObserver в `WorldScreen`; при открытом поиске или профиле 0). Пункт — `<button data-list-region>`: нажатие — `onSelectRegion` (как полигон), наведение мышью и фокус подсвечивают регион на карте (`listId` в `MapStage`, без подсказки), пока камера летит в мир — список прозрачен и не нажимается. Узкий список (≤ 16rem, телефон боком) — число героев под названием (container query). Строка-подсказка мира (`WorldHint`) на телефоне не показывается.

## A14. Качество: доступность, производительность, браузеры

SPEC §14, эпик E11.

**Клавиатура.** В мире Tab идёт по полигонам регионов (`role="button"`, `tabindex="0"`, порядок — порядок в `layout.json`), в регионе и месте — по маркерам мест, затем по панели. Enter и пробел открывают, Esc — на уровень вверх (A11 — порядок Esc). Фокус с клавиатуры показывает ту же подсветку и подсказку, что и наведение (A4).
- Фокус не теряется при переходе (`features/world/focus.ts`, вызывается из `WorldScreen` при смене экрана). Если элемент с фокусом пропал, скрыт или перестал быть фокусируемым (полигон в S2 — уже не кнопка, крошки уехали с панелью), фокус ставится: вверх (место → регион, регион → мир) — на маркер места или полигон региона, откуда пришли (на телефоне регион, открытый пунктом списка регионов, — на этот пункт: `WorldScreen` помнит источник, `onSelectRegion(id, 'list' | 'map')`, `restoreFocus(…, { listRegionId })`; пункт прокручивается в видимую часть только внутри списка); вниз и вбок — на заголовок панели (`h2` с `tabindex="-1"` и `data-panel-heading`, без кольца — `[tabindex='-1']:focus` в `global.css`). Фокус, который пользователь держит, не трогаем; `focus({ preventScroll: true })`.
- Окна (галерея, «О проекте», обратная связь) — A8: ловушка фокуса (`components/focusTrap.ts`: с #73 знает поля ввода и фокус на самом окне), возврат на кнопку-источник.
- Подсказка региона в мире (SPEC §6.2, #65) — портал в конце `body`, поэтому порядок Tab ведёт `MapStage`: Tab на полигоне ставит фокус на первую кнопку подсказки, Shift+Tab с первой — на полигон, Tab с последней — `focusAfter` (`features/world/focus.ts`): следующий по порядку Tab элемент после полигона, минуя саму подсказку. Пока фокус в подсказке, она важнее наведения мыши (иначе пропала бы вместе с фокусом). Esc закрывает её и останавливает всплытие, чтобы глобальный Esc (`App`) не снял героя. `mousedown` в подсказке гасится — клик мышью не оставляет в ней фокус. Роль: с кнопками — `group` с именем региона, без героев — `tooltip`.

**Контраст (WCAG AA).** Цвета текста — `--text-1…3`, `--metal-bright`, `--neutral`, `--radiant` — ≥ 4.5:1 на `--bg-0…2`; кольцо фокуса `--accent-bright` ≥ 3:1 (WCAG 1.4.11). Красный `--accent` и тёмный металл — только рамки и заливки, не текст (на `--bg-2` у `--accent` 2.9:1); выбранный язык — светлый текст на `--accent-dim`. Имя ссылки или кнопки с видимым текстом начинается с этого текста (WCAG 2.5.3: «dota2.com: …», «+N: …»). Приглушённый текст (пункты списка регионов без выбранного героя) — цвет `--text-3`, не `opacity` (axe в e2e). Проверяет `src/styles/quality.test.ts` по `tokens.css` и CSS-модулям.

**Картинки.** У каждого `<img>` есть `alt`: портрет-ссылка — `alt=""` (имя у ссылки), портрет без ссылки — имя героя, картинка галереи — название медиа, шапка места — `alt=""` (декор). Проверяет `quality.test.ts`.

**prefers-reduced-motion.** Токены длительностей укорачиваются в `global.css` (A8). Кроме того, каждый CSS-файл с движением — бесконечной анимацией или ключевыми кадрами со сдвигом/масштабом — сам выключает его в `@media (prefers-reduced-motion: reduce)`: панель и шторка появляются без выезда, нить нарисована сразу и не течёт, подсказка и плашка героя без сдвига, медиа галереи без увеличения, карта под интро без масштаба, облака без дрейфа, спиннер без вращения; камера — кроссфейд (A4), частиц нет (A12). Новый файл с движением без такого блока роняет `quality.test.ts`.

**Бюджет загрузки.** До мира грузятся `index.html`, бандл JS и CSS (данные мира внутри бандла) и шрифты Google Fonts; портреты и медиа с CDN Valve — только в мире (панели, подсказки, галерея; портреты `loading="lazy"`). `scripts/check-budget.mjs` (часть `npm run check`) считает gzip html/js/css из `dist` и падает, если бандл > 600 КБ или вместе с оценкой шрифтов (400 КБ) > 3 МБ. Картинка галереи грузится без `lazy` (она видна сразу и обычно — самый крупный элемент) и занимает всю ячейку (`object-fit: contain`), чтобы кадр не прыгал при загрузке.

**Замеры.** Lighthouse (desktop) — `npx lighthouse <url> --preset=desktop` по `npm run preview`: интро, мир, регион, место, галерея, выбранный герой. Цифры последнего замера — в PROJECT_STATE.
- Автоматически (e2e, A7) на всех четырёх проектах: `@axe-core/playwright` на шести экранах (интро, мир, регион, место, галерея, профиль) — нарушений `serious`/`critical` нет; с `reducedMotion: 'reduce'` в мире, регионе и месте после посадки камеры `document.getAnimations()` без бегущих (`running`) анимаций.

## A16. Обратная связь (E17, #73, #74)

- Код — `features/feedback/`: `message.ts` (чистые функции формата issue и ссылки), `context.ts` (контекст из адреса: `feedbackContext(route, lang, href, block?, kind?)`; блоки `regionBlock`, `placeBlock`, `heroBlock`, `mediaBlock`), `draft.ts` (черновик в `localStorage` под try/catch, ключ `dota-lore-map.feedback.draft`), `FeedbackProvider.tsx` (одно окно на приложение, `useFeedback()`: `isOpen`, `open(request?)`, `close`, `toggle`), `FeedbackWindow.tsx` (окно, SPEC §6.9), `FeedbackLink.tsx` (строка «Нашли ошибку?» в конце блока, #74). Провайдер — в `App` внутри `NavigationProvider`: окну нужен адрес для контекста.
- **Формат** — один на все способы отправки. `feedbackIssue(message, ctx)` → `{ title, body }` целиком; `feedbackUrl(repo, message, ctx)` — ссылка `<repo>/issues/new?title=…&body=…&labels=feedback`. Подписи — по языку интерфейса (`ctx.lang`), таблица — в самом `message.ts` (это текст issue, а не интерфейса). Значение контекста обрезается до 300 символов (адрес набирает пользователь).
- **Длина ссылки — `URL_LIMIT` = 6700 знаков.** Замер 2026-11-15 запросами без входа: GitHub переадресует на вход ссылки до ~6890 знаков, длиннее — отвечает 500, от ~9000 — 414; с входом лимит не мерили. Сообщение 1000 символов кириллицы — 6000 знаков, поэтому сообщение не сокращается никогда, а уходит контекст: строки — по важности (адрес, блок, экран, регион, место, герой, медиа, версия, язык) с конца, адрес — после выдержки в заголовке. Не помещается само сообщение — `null`, окно просит сократить.
- **Метка из ссылки** (`labels=feedback`) GitHub применяет только при правах triage; у посетителей issue создаётся без метки. Логика проекта на метку не опирается.
- **Версия сборки** — `__APP_VERSION__` из `vite.config.ts` (`define`): `version` из `package.json` (её ведёт release-please, руками не правим) + `+<короткий хеш>` (`GITHUB_SHA` в CI, иначе `git rev-parse`; без git — только версия). Читается через `src/app/project.ts` (`BUILD_VERSION`, там же `REPO_URL`).
- **Отправка** — ссылка `<a target="_blank" rel="noopener noreferrer">`, а не `window.open`: её не режет блокировщик всплывающих окон. Очистка черновика и сообщение «форма открыта» — в `setTimeout(0)` после клика: ссылка, убранная из DOM во время клика, никуда не переходит.
- **Закрытие**: ×, Esc (в окне — `stopPropagation`; если фокус ушёл из окна — первая ветка Esc в `App`, A11), `pointerdown` вне окна (capture на `document`), повторный клик по кнопке. Кнопки с атрибутом `data-feedback-opener` кликом «вне окна» не считаются — они переключают окно сами. Фокус при закрытии — на кнопку-источник, если он был в окне или пропал.
- **Отзыв о блоке (#74).** `FeedbackLink` в конце блока вызывает `open({ block })`, `block` — `FeedbackBlockRef` `{ type: 'region' | 'place' | 'hero' | 'media', id, name: Localized }`: название на обоих языках, имя для окна и issue берётся по языку интерфейса в момент отправки (смена языка при открытом окне меняет и то, и другое). id места — `<регион>/<место>`; у медиа — id из данных или id арта профиля (`hero-<key>-…`, в `World.media` их нет — поэтому название несёт сама ссылка, а не ищется по id). Вид (`FeedbackKind`: `error` | `addition` | `other`) — состояние окна, по умолчанию `error`. Формат тот же `message.ts`: заголовок по виду, строки «Блок» и «Вид» сразу после адреса (уходят из ссылки последними после адреса), метки `feedback` + `content-fix` (`feedbackLabels`). Окно с другим блоком — новое (`key` по блоку): вид сбрасывается, фокус вернётся на строку, открывшую его. Строки — кнопки с `data-feedback-opener`: клик по другой строке при открытом окне переключает окно на её блок.
- **Слой и клавиши.** Окно — `z-index: 120`, выше галереи (110) и «О проекте» (100): из галереи его открывает строка медиа. Галерея, пока окно открыто (`useFeedback().isOpen`), не обрабатывает свои клавиши на `window` — стрелки в поле не листают, Esc закрывает окно (A11), а не галерею. Клик по затемнению галереи при открытом окне закрывает окно (`pointerdown`) и галерею (`click`) — сознательно не разделяли.
